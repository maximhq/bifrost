## Changelog

v2.7.0 moves the enterprise gateway onto OSS transports v2.7.0. Members can connect, refresh and disconnect their own MCP server credentials from Home with only MCP Gateway View access, and budget request notifications resolve once a request is decided. Cluster governance accounting gets a set of fixes for usage that was lost, counted twice or went negative across leader changes, node failures and resets. The OSS release adds the Gemini Interactions API, client credentials and AWS SigV4 auth for upstream MCP servers, and async jobs on relays.

## ✨ Features

- **Connect Your Own MCP Servers from Home** - The My access tab on Home shows each MCP server's auth type, discovery mode, tools, grant source and a Connection badge for the signed-in user. Users can connect, reconnect, load or refresh tools, update their header keys and disconnect from that tab, and servers granted through Virtual MCPs now appear in the same table. [Docs](https://docs.getbifrost.ai/mcp/sessions)
- **MCP Credential Self-Service for View Roles** - `/api/mcp/sessions/connect`, session revoke, session refresh and `/api/mcp/per-user-headers/credential/{id}` are now gated on `MCPGateway:View`, so a view-only member can manage their own MCP sign-ins. Refreshing another user's credential still needs `MCPGateway:Create`, and revoking it still needs `MCPGateway:Delete`.
- **MCP Clients on /users/me** - `GET /users/me` returns an `mcp_clients` map with every MCP client the caller may call, through their own access profiles, clients allowed by default, or an active virtual key they hold. Each entry carries `name`, `auth_type`, `per_user_discovery`, `awaiting_verification` and `disabled`.
- **Budget Request Notifications Resolve on Decision** - The "Budget increase requested" notification is resolved for every approver once the request is approved, denied or cancelled. The outcome line names who decided it, repeats the amount and duration only when the approver changed them, and the link opens the approvals tab on that request.

## 🌎 Open Source Features

- **Gemini Interactions API** - Gemini and Vertex serve Responses requests through Google's Interactions API when a request sets `previous_response_id`, sets `background: true`, names an agent such as Deep Research, or uses a Google-run `tool_search`, with retrieve, cancel and delete. The `/genai` integration adds typed `/interactions` routes in the Gemini and Vertex path shapes, so governance, logging, pricing and fallbacks apply, and a run is billed once. [Docs](https://docs.getbifrost.ai/providers/supported-providers/gemini)
- **Per-Key and Per-Alias Service Tier** - A key or a key alias can set `service_tier`, sent on chat completions and Responses requests in place of the request's own tier. An alias's tier overrides its key's, so a spare weight-0 key set to `priority` can serve Priority traffic only when rotation reaches it.
- **MCP OAuth Client Credentials** - New `client_credentials` auth type for upstream MCP servers. Bifrost mints one shared token with the OAuth client credentials grant (`client_secret_basic`, `client_secret_post` or `private_key_jwt`), caches it per client and backs off on a refused credential. Set from the MCP client form, config.json or Helm. [Docs](https://docs.getbifrost.ai/mcp/auth/client-credentials)
- **MCP AWS SigV4 Auth** - New `aws_sigv4` auth type for upstream MCP servers. Bifrost signs each request with its own AWS identity from the default credential chain, with an optional assumed role, to reach IAM-protected servers such as Amazon Bedrock AgentCore Gateway. [Docs](https://docs.getbifrost.ai/mcp/auth/aws-sigv4)
- **MCP OAuth on Several Hostnames** - `oauth2_server_config.browser_base_url` sets the host that users' browsers open for the consent and device flow pages, and `additional_issuer_urls` (up to 10) lets one instance act as the OAuth issuer on other hostnames. Both are editable under Security settings.
- **MCP Progress Notifications** - The `/mcp` gateway relays upstream `notifications/progress` on `tools/call` to a caller that sends a `_meta.progressToken`, under the caller's own token and ahead of the result.
- **MCP Session Connect** - `POST /api/mcp/sessions/connect` lets a signed-in user start their own sign-in to a per-user OAuth or per-user headers MCP client, and returns them to the page where the sign-in started. Revoke and refresh on another user's session need the matching permission. [Docs](https://docs.getbifrost.ai/mcp/sessions)
- **Relay Async Jobs** - A relay route can declare a `job` for APIs such as AWS Textract that start background work and report the price only when it finishes. Bifrost polls the job, charges it once when it ends, relays callers' own status checks free, and shows how each job ended in Relay Logs, with settled costs reaching OTel and Prometheus. [Docs](https://docs.getbifrost.ai/relays/async-jobs)
- **Relay Enforced Body Fields** - `body_overrides` on a relay or a route forces JSON fields into every request body, whatever the caller sent. A route's value replaces the relay's, and `inherit_body_overrides: false` leaves the relay's fields out of a route. [Docs](https://docs.getbifrost.ai/relays/configuration)
- **Relay Route Matching** - A route path can hold one `**` in the middle, such as `/jobs/**/status`. Routes are tried most specific first instead of in list order, and the dashboard lists them in that order. [Docs](https://docs.getbifrost.ai/relays/routes)
  <Note>
  A broad route no longer shadows a narrower one by sitting above it. A wildcard segment never matches `.` or `..`, and a dot-segment path that matches no route is refused.
  </Note>
- **OpenAI Prewarm and Background Options** - Responses requests accept `prompt_cache_options.prewarm`, `prompt_cache_options.comparison_response_id` and `background_options` as typed fields. A prewarm request gets its own semantic cache key.
- **OpenAI Access Programs** - Responses requests accept `access_programs` on HTTP and WebSocket, forwarded to OpenAI only, and the program that served the request is returned.
- **Vertex Batch Embeddings** - Vertex Gemini embedding models accept more than one input per request through `:batchEmbedContents`.
- **Bedrock Credential Caching** - A Bedrock key with no static credentials loads the AWS default credential chain once per region instead of on every request.

## 🐞 Fixed

- **Expired Archived Usage on Reset** - When a limit's window resets, the leader discards archived usage from the closed window per dimension instead of subtracting it from an already zeroed counter, which could drive rate-limit usage negative
- **Leader Governance State** - Followers install the leader's baselines atomically per limit, so concurrent charges are not lost, closed-window usage does not carry forward, and state from a former leader or out-of-order captures is rejected
- **Ghost Recovery Double Counting** - The leader's ghost log recovery no longer counts the same requests twice after a node resumes, a log entry changes mid-query, or a node is still on DB-loaded baselines
- **Archive Transfers** - Archiving or restoring a dead node's usage is atomic to request checks, archival rechecks the node is still dead, restores drop closed-window usage, and a failed operator purge is reported as failed
- **Exact Governance Clocks in Cluster Metadata** - Nanosecond reset boundaries and clocks reach the governance plugin exactly instead of losing precision in JSON number decoding
- **Access Profile Limit Baselines** - A budget or rate limit loaded from the database publishes its usage and persisted baseline together, and dropping an access profile from a user evicts its scoped model configs
- **Calendar Alignment for Projects and Business Units** - Turning on calendar alignment moves open budget and rate-limit windows to the calendar boundary and keeps their current usage instead of resetting it
- **RBAC Changes** - Changing a user's role with `preserve_virtual_keys: false` rotates their virtual keys first, and governance reloads finish their in-memory update and cluster broadcast even when the RBAC refresh fails
- **Cluster Broker Roster and Metadata** - A node forgets a broker's roster when its heartbeat session ends, and startup fails with a clear error instead of a panic when memberlist metadata exceeds 512 bytes
- **MCP Client Refetch on Peers** - Peer nodes refetching an MCP client now receive its `client_credentials` and `aws_sigv4` settings
- **Load Balancer Stream Attribution** - Stream chunks are accumulated synchronously, so attribution no longer races with request cleanup
- **Relay Job Settlement Metrics** - Datadog and Splunk count a settled relay async job's charge in relay cost without recording a phantom relay call
- **Root-Level Union Tool Schemas** - MCP tools whose input schema is a root-level `oneOf`, `anyOf` or `allOf` keep their parameters through discovery and `/mcp` listing
- **Bedrock Document Blocks** - `/bedrock` InvokeModel forwards Anthropic `document` blocks, including URL sources, and returns a 4xx for input it cannot forward
- **Bedrock Tool Results** - The `/bedrock` invoke and Converse routes carry every member of a tool result, including images and documents
- **Bedrock Reasoning-Only Responses** - A Converse response cut off at `max_tokens` while reasoning returns the reasoning block instead of an empty message
- **Bedrock Grok Reasoning Replay** - Signed reasoning from Grok models on Bedrock is replayed on later turns
- **OpenRouter Reasoning Details** - `reasoning_details` are replayed on assistant messages sent to OpenRouter, so Claude no longer re-reasons on every tool-call turn
- **OpenRouter prompt_cache_options** - OpenRouter Responses requests send `prompt_cache_options` only with mode `explicit`
- **Anthropic Signed Thinking Blocks** - Signed thinking blocks with empty text are kept on multi-turn requests
- **Claude Code Reasoning Retry** - The strip-and-retry for a refused foreign `redacted_thinking` block runs on `/anthropic/v1/messages` for Claude Code
- **Advisor Tool Aliases** - An Anthropic advisor tool's model is resolved through the key's aliases
- **Codex Replayed Function Calls** - `summary` is sent only on reasoning items, so replayed `function_call` items with `encrypted_content` are accepted by OpenAI
- **OpenAI Image Edits by URL** - Image edits that reference an input image by URL work on OpenAI and Azure
- **Vertex Roleless Items** - Responses items with no role get a role before they are sent to Vertex Gemini
- **Vertex Passthrough Body Rewrite** - The Vertex passthrough rewrites only `model`, `cachedContent` and `operationName` and no longer alters prompt text
- **Vertex Batch Partner Models** - Vertex batch creation accepts `<publisher>/<id>` model names
- **Vertex Priority Tier** - Priority PayGo is accepted on the `us` and `eu` multi-region endpoints as well as `global`
- **MCP Tools Without a Description** - MCP tools with no description no longer fail on Bedrock Converse
- **MCP Refresh Token Race** - Replicas sharing a config store no longer redeem the same MCP refresh token at the same time
- **Failed Stream Spans** - A stream that ends on a read error is traced as failed instead of successful
- **OTel Metric Labels** - OTel metrics carry the same labels as Prometheus (`alias`, `app`, `routing_engine_used`, `routing_rule_id`, `routing_rule_name`, `complexity_tier`)
- **Relay Caller Overrides** - A caller can no longer replace a relay's `extra_headers`, switch the method with `X-HTTP-Method-Override`, or pass its own query credential
- **Relay Timeout Errors** - A relay timeout names the relay and the timeout that fired, and billed request bodies allow 1000 levels of nesting instead of 64
- **Relay Span Dimensions** - Relay spans carry the same user, app, team and customer dimensions as LLM spans
- **Usage Lost on Config Refresh** - A budget or rate-limit charge that lands during a config refresh is no longer lost, and a refresh cannot move a reset boundary backward
- **Usage Baselines** - Budget and rate-limit resets and dumps update usage and its persisted baseline together
- **Virtual Key Reload Race** - Overlapping reloads of one virtual key are serialized, so a rotated-out key value cannot come back
- **Firefox Dashboard Banner** - Firefox no longer shows the "Part of the dashboard couldn't load" banner on every page
- **Onboarding Checklist** - The onboarding checklist no longer loads every virtual key on each dashboard page

## 🗄️ Database Migrations

### Enterprise

No new enterprise migrations in this release.

### Open Source

<Warning>
This release changes the `relay_logs` table (`relay_logs_add_job_debug_widen_job_status`): it adds the `job_debug` column and widens `job_status`. Bifrost handles concurrent access on the application side, but on large log tables the change still takes locks and adds load. Deploy during a low-traffic window.
</Warning>

- **add_key_service_tier_column** - Adds a nullable `service_tier` column to provider keys. Reversible: drops the column.
- **widen_batch_jobs_provider_status_and_endpoint** - Widens `batch_jobs.provider_status` and `endpoint` to `TEXT` on Postgres. Non-reversible: narrowing the columns would cut stored relay job statuses and routes.
- **add_mcp_client_client_credentials_json_column** - Adds the client credentials config column to MCP clients. Reversible: drops the column.
- **add_mcp_client_aws_sigv4_json_column** - Adds the AWS SigV4 config column to MCP clients. Reversible: drops the column.
- **add_mcp_oauth_flow_origin_column** - Adds an `origin` column to `mcp_oauth_flows`. Reversible: drops the column.
- **add_notification_subject_resolution_columns** - Adds `subject_type`, `subject_id`, `resolved_at` and `resolution` to notifications. Reversible: drops the columns.
- **add_notification_subject_index** - Adds `idx_notifications_subject`, built concurrently. Reversible: drops the index.
- **relay_logs_add_job_debug_widen_job_status** - Adds a nullable `job_debug` column to `relay_logs` and widens `job_status` to `TEXT` on Postgres. Non-reversible: dropping `job_debug` or narrowing `job_status` would lose recorded job details.
