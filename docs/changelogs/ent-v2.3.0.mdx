## Changelog

v2.3.0 moves the enterprise gateway onto OSS transports v2.3.0. Teams, business units and customers can now hold an access profile that governs every member and key under them. Adaptive routing now holds provider keys that a provider refuses and rechecks them, and it records a routing history with an Incidents page. Alerting adds business unit and user scopes, plus rules that watch every entity of a scope and send one digest per channel. Identity sync adds reconcile with preview, one directory sync job that also deprovisions users, and attribute-to-project rules. The OSS release adds the A2A Agent Gateway, GPT Live sessions, the Cloudflare Workers AI provider, and provider-injected MCP tools.

## ✨ Features

- **Access Profiles on Teams, Business Units and Customers** - A team, business unit or customer can hold an access profile (`GET/POST/DELETE /api/governance/{teams|business-units|customers}/{id}/access-profile`). Members' requests and the keys the entity owns are then governed and charged by that profile. An entity profile adds to a member's own profiles and never removes access. Attaching to an entity that still has its own limits returns 409 `entity_has_legacy_limits` with a migration plan. `POST .../access-profile/migrate` (dry run supported) builds a profile from the old limits, carries spend over on the same reset window and adopts the entity's keys. Assign Existing adopts a key into the entity profile. config.json accepts `access_profile` on `governance.teams`, `governance.customers` and `governance.business_units`. The entity sheets have Attach, Detach and Migrate actions, a migration wizard and a Usage tab. [Docs](https://docs.getbifrost.ai/enterprise/access-profiles)
- **Business Unit Ownership and Limits** - A virtual key can be owned by a business unit (`business_unit_id`). That key spends the unit's budget and rate limit and those of the customers the unit serves. Business units have their own budget and rate limit (`/api/governance/business-units/{id}/governance`), and like teams they use either their own limits or a profile, never both. Deleting a business unit unassigns its keys in the database, in memory and on peers.
- **Business Unit and Customer Data Scopes** - Roles can use two new data scopes. `business-unit-data` covers the caller's business units, their members and keys owned by those units. `customer-data` covers every team and business unit under the caller's customers, plus keys owned by those customers. Both scopes can be selected in the role editor and set in config.json.
- **Agent Access Grants** - Access profiles and projects can grant Agent Gateway agents by name with `agent_grants`. On project update, omitting the field keeps the current grants, and an empty list clears them. Blank, duplicate and unregistered names are rejected. A2A bearer calls resolve the user through the IdP, and the agent log records the user with their team, customer and business unit. New RBAC resources are `AgentGateway` and `AgentLogs`, and agent log reads are DAC-scoped. Agents also appear in the Home, user detail and Activity views.
- **Home Page** - Each user gets a Home page with:
  - spend, requests, top model, the budget closest to its limit, and spend rank;
  - cost and model charts, app usage, and a budget burn chart with a projection;
  - their keys and access. My Access shows disabled MCP servers and folds long tool lists.

  Endpoints: `GET /api/governance/users/me` and `GET /api/governance/users/me/rank`. A weekly `token_monster` badge goes to the top 10 spenders.
- **Budget Increase Requests** - Users can request more budget on a virtual key or access-profile budget they own (`/api/governance/users/me/budget-requests`). Approvers with `VirtualKeys:Update` approve or deny requests under `/api/governance/budget-requests`, and a deny needs a note. On approval, `override_strategy` sets how the amount is applied: `add` (default), `replace`, or `add_keep_lifetime`. Approvers are notified, and each budget can have only one pending request. Home splits decided requests into Approved and Denied tabs.
- **Org Chart** - New Governance page. It shows business units, teams and users, or customers, business units and teams, as a drill-down tree. Each level shows its top five children by spend, tokens, requests, budget or name. Nodes show a budget meter for the current cycle or a strip of the last 3, 6 or 12 cycles, and `/` jumps to any node. Every list is DAC-scoped (`/api/governance/org-chart/*`).
- **Activity Tab on Entity Sheets** - Every entity detail sheet has an Activity tab. It shows spend against the previous period, tokens, requests, budget left, per-cycle budget history, spend by model, and models and MCP tools tables. Team sheets also rank members by spend.
- **Provider Key Holds in Adaptive Routing** - When a provider refuses a key for a reason that will repeat (credential, model_access, quota, model_gone, region_blocked, rate_limit), that key is taken out of rotation for the affected route. The whole key is held only for a rejected credential or an org-wide quota refusal. After the wait, exactly one request goes through as a recheck. A clean answer releases the key. A failure moves it up a doubling backoff that starts at 30s, with caps from 5m to 30m by reason. A 429 holds the key for the provider's `Retry-After`, which replaces the TPM circuit breaker. Holds are shared with cluster peers, survive restarts, and are fetched by joining nodes. `GET /api/adaptive-routing/conditions` lists holds, and `POST /api/adaptive-routing/conditions/clear` releases them across the cluster for one key, one provider, or all keys. [Docs](https://docs.getbifrost.ai/enterprise/adaptive-load-balancing)
- **Adaptive Routing History and Incidents** - Each node records routing frames and events: health changes, weight changes, holds, settings edits, key edits and node boots. Storage is SQLite, Postgres or ClickHouse, with its own `history_retention_days` (1-30, default 7) and a `history_enabled` switch. The Adaptive Routing dashboard is rebuilt on this history:
  - provider, model, region and node filters, and a Live toggle;
  - a paged health timeline with a routing score breakdown;
  - held-keys and state sheets.

  A new Incidents page (`/workspace/adaptive-routing/incidents`) lists issues merged across nodes. Each issue shows its status, the recent config changes around it, nodes whose hold came from a peer, and whether an operator is needed. Read APIs are under `/api/adaptive-routing/history/`. The dashboard needs a Postgres or ClickHouse log store.
- **Routing Decision Metadata on Logs** - Each attempt writes `bifrost_alb_*` metadata to its log: decision, requested provider and model, reroute target, excluded providers, key decision and skip reasons, failure class and region. An Adaptive Routing card on the log's Routing tab shows these values, and the Logs sidebar has an Adaptive Routing filter group.
- **Adaptive Routing Settings** - New `reroute_target` (`pool`, the default, or `fallbacks`). With `fallbacks`, a failed pinned request moves to its own first healthy fallback. A direction where only some keys fail is now `Degraded` and stays in rotation. `snapshot_persist_interval_seconds` is configurable, and its default changes from 30s to 5 minutes. A circuit breaker now follows a chain of open circuits to the first healthy target, with loop protection. Config and conditions routes move to `/api/adaptive-routing/`, and `/api/load-balancer-config` stays as a deprecated alias. UI labels are renamed: Reroute is now Redirect, and Prune Failed Fallbacks is now Skip Failing Fallbacks.
- **Identity Reconcile with Preview** - `POST /api/scim/provision/reconcile` replays stored login claims or SCIM state, so a mapping edit reaches existing users. It accepts an optional `user_ids` subset. The preview reports per-user changes without writing anything: role, teams, business units, projects, access profiles, and keys revoked or created. `.../reconcile/preview/user` shows the plan for one user. After you save a mapping, the provider wizard offers to reconcile. The provisioning dashboard's Re-verify action becomes "Reconcile users".
- **Unified Directory Sync with Deprovisioning** - The Sync users button, `/api/scim/provision/sync` and the scheduled run now execute one job. It creates or restores listed users and reconciles teams, business units, projects, roles and access profiles. After a complete listing, it deprovisions users the IdP no longer lists, and where the provider supports it, it first confirms the user is inactive. Service accounts and manual users are never touched. `bulkSyncInterval` (1h-30d, default 24h) applies without a restart. With SCIM provisioning on, bulk import and team or business-unit pulls return 403.
- **Attribute-to-Project Mapping** - New `attributeProjectMappings` rules add users to existing projects from IdP attributes on login, refresh, directory sync and SCIM pushes. A sync removes only the members its rules added, and members a rule adds show a "Synced from IdP" badge.
- **Identity Mapping Rules** - Several changes to how mapping rules work:
  - A glob rule value can contain more than one `${*}`.
  - Role and access-profile rules are stored by entity ID, so renaming a role or profile no longer breaks them. A rule that names a missing entity is reported in `skipped_mappings`.
  - An interactive login now replaces claim memory, so an attribute the token omits removes what it granted. A login whose token has none of the role-rule attributes is refused with a 403 that names the missing attributes, and the user's existing role is kept.
  - On a role tie, the rule higher in the list wins.
  - New SCIM group rules match on displayName.
- **SSO Provider Options** - Every SSO provider accepts `emailField`, the token claim that holds the email (for example `upn` or a namespaced Auth0 claim). The generic OIDC provider accepts `displayName` for its login button. The `bifrost-cli` PKCE client is accepted, and CLI sessions do not use Edge device seats. Deploy this gateway before the OSS CLI release.
- **Alerting: Business Unit and User Scopes** - Alert rules accept two new scopes. `business_unit` watches a unit's budget and rate limit. `user` targets one user's budget or, for user scope only, a `rate_limit`. Limits a user holds through access profiles and model configs are checked against their own targets and reset cycles. `GET /api/alerting/users/{id}/targets` lists the targets for a user, and the rule form adds a user picker and a limit picker. Rules are removed when their user or business unit is deleted. [Docs](https://docs.getbifrost.ai/enterprise/alerting/alert-rules)
- **Alerting: Rules for All Entities with Digests** - Every scope accepts `scope_id: "*"` (UI: Applies To > All). The rule then checks each virtual key, team, customer, business unit or user against its own limits. When several entities match in one pass, each channel gets one digest message, with rich layouts for Slack, Teams and PagerDuty. Cooldown and recovery are tracked per entity. History rows carry `rule_scope_id`, `digest_id` and `digest_size`, and the UI shows "All" and "Digest of N" badges.
- **Alerting: Access-Profile Budgets** - Budgets held through access profiles now raise alerts.
- **Alerting: History Sorting and Paging** - `GET /api/alerting/history` accepts `sort_by` (`created_at`, `rule_name`, `channel_name`, `scope_type`, `status`) and `sort_order`. The default is `created_at` descending. The history table sorts on the server and shows absolute and relative times. History defaults to a 7-day window, caps its count at 10,000+ (`total_capped`), and pages by keyset.
- **Guardrail Updates** - New A10 TrojAI Defend provider (`a10`, with `base_url` and `client_id`). Other changes:
  - Profiles on a rule run in a set execution order.
  - The rule builder has a Builder / CEL toggle.
  - Detect-only matches on Regex, Secrets, Presidio, Azure PII, Lakera and Bedrock are recorded as detections.
  - Azure PII, Presidio and regex accept `allowed_values`, values that are never blocked or redacted (up to 10,000).
  - Bedrock assessments include `confidence`.

  [Docs](https://docs.getbifrost.ai/enterprise/guardrails)
- **Connector Export Updates** - New export options for BigQuery, Datadog, Splunk, Kafka and Pub/Sub:
  - Per-category cost breakdown on all five. BigQuery adds 19 columns for it.
  - `excluded_attributes` drops listed attributes before export.
  - BigQuery `export_raw_payloads` writes provider bodies to `raw_request`/`raw_response`, and a new `app` column records the calling client.
  - Datadog `metric_dimensions` sends listed `x-bf-dim-*` dimensions as metric tags. Datadog and Splunk metrics carry `user_id` and `user_name`.
- **Audit Logs Without IP Addresses** - New `audit_logs.omit_ip_addresses` stops storing client IPs. IPs in earlier rows are redacted on every read and export path. IP search and filters are disabled, and signatures stay valid. [Docs](https://docs.getbifrost.ai/enterprise/audit-logs)
- **Warp in Enterprise** - New `Warp` RBAC resource. Admin has View and Update, Developer and Viewer have View, and the log-index backfill needs Update. Warp follows the caller's data scope, and `describe_user_limits` reports access-profile budgets and rate limits from live counters. [Docs](https://docs.getbifrost.ai/features/warp)
- **RBAC Updates** - New `BackgroundJobs` resource for `/api/sidekiq/jobs`: View to list, Update to cancel. Add, edit and delete actions across guardrails, prompt deployments, Edge approvals and access profiles are hidden or disabled when the role lacks the permission.
- **Bounded Audit Log Queries** - Audit log search needs at least 3 characters and defaults to a 30-day window. Counts cap at 10,000+ (`total_capped`), and paging is keyset.
- **Edge Server Support** - Admins can turn off Edge capture for one app, fleet-wide or per user or team (`PUT /edge/interception` with `app_key`). Edge Devices shows the installed Edge version. New `/mcp/inspect/v2` lets MCP post-inspection run on any node, with no session affinity. Cursor config accepts per-operation models (`linter_model`, `embedding_model`, `speech_model`, `image_model`, `video_model`, `transcription_model` and others). [Docs](https://docs.getbifrost.ai/edge/overview)
- **MCP in Clusters** - MCP server instructions are saved and sent to peers with discovered tools. Refreshing a client's tools makes every peer re-discover them right away.

## 🌎 Open Source Features

- **Agent Gateway (A2A)** - Bifrost proxies A2A agents. Register an agent by its card URL (`POST /api/agents` or the config.json `agents` array). Clients reach it over JSON-RPC (with SSE streaming), REST, or an optional shared gRPC listener. It supports header, OAuth and TLS upstream auth, and push notifications through a durable, retried outbox. Access is granted per virtual key with `agent_grants`. Every operation is logged in a new Agent Logs workspace.
- **Warp AI Assistant (alpha)** - In-dashboard assistant that answers questions about logs, spend, latency and governance with read-only tools, inline charts and links to matching log rows. Completed logs can be embedded for semantic search, with a resumable backfill. Warp is off by default in Enterprise (`warp` feature flag). [Docs](https://docs.getbifrost.ai/features/warp)
- **GPT Live Sessions** - Proxies OpenAI GPT Live over WebSocket and WebRTC at `/v1/live/sessions`, with sideband attach and recording download. Voice is billed in 30-second windows, governance is checked at each window, and `live` is its own allowed request type.
- **Cloudflare Workers AI Provider** - New `cloudflare` provider for chat (streaming included), Responses, embeddings and model listing. Each key needs `cloudflare_key_config.account_id`. A dialog in the UI migrates an existing custom provider named `cloudflare`. [Docs](https://docs.getbifrost.ai/providers/supported-providers/cloudflare)
- **Provider-Injected MCP Tools** - A provider's `injected_tools` adds MCP tools to every chat and Responses request for that provider. Bifrost runs them server side and returns only the final answer. An entry named `web_search` replaces native web search. Configure it in the provider's new Tools tab.
- **OAuth-Minted Keys for OpenAI-Compatible Providers** - `oauth_key_config` mints a bearer token with the `client_credentials` or `jwt_bearer` grant, caches it, and refreshes it before expiry. Databricks and GitHub Copilot use the same token cache.
- **Decisions API Updates** - `/v1/decisions` takes OpenAI-shaped `input` and `questions`, and new `/openai/v1/decisions` routes accept the OpenAI SDK request. Native decision models are reached on OpenAI, Perplexity, Ollama and OpenRouter. TypeSafe can be a custom provider base, and decisions have their own pricing fields. Emulation on non-decision models is now opt-in through `convert_decision_to_responses`. [Docs](https://docs.getbifrost.ai/quickstart/gateway/decisions)
- **Complexity Router Decision Classifier** - The complexity router can classify with a decision model (TypeSafe Jev by default), as the primary classifier or as a fallback. Per-tier guidance is editable. [Docs](https://docs.getbifrost.ai/features/complexity-router)
- **Multimodal Embeddings** - `/v1/embeddings` accepts text, image, audio, video, file and token parts, served by Cohere, Gemini, Vertex and Bedrock (Nova and Titan multimodal). Parasail now serves embeddings.
- **Responses Tools** - Adds OpenAI `shell` and `apply_patch` tools, maps `allowed_callers` between OpenAI and Anthropic, and maps Gemini code execution to `code_interpreter_call`.
- **Retrieve a Single Model** - `GET /v1/models/{model}` for OpenAI, Anthropic, Cohere, Gemini, Mistral and Ollama, with `shutdown_date` where the provider announces one.
- **xAI Realtime** - xAI is a realtime voice provider on the WebSocket gateway, with client-secret minting. [Docs](https://docs.getbifrost.ai/providers/supported-providers/xai)
- **Bedrock Passthrough** - `/bedrock_passthrough` forwards InvokeAgent, knowledge-base Retrieve and ApplyGuardrail, SigV4-signed with the key's AWS credentials. [Docs](https://docs.getbifrost.ai/providers/supported-providers/bedrock)
- **Vertex Workload Identity from AWS** - `vertex_key_config.aws_workload_identity` authenticates from EKS IRSA, Pod Identity, ECS task roles or EC2 instance profiles, with no stored key.
- **Pricing Updates** - Web search is billed per request (`web_search_cost_per_request`), and existing values are migrated. `*_above_100k_tokens` rates apply above 100,000 prompt tokens. A per-provider `ignore_provider_cost` setting prices requests from the catalog instead of the provider's reported cost.
- **Compat Updates** - `force_reasoning_only_models_to_responses` (default `true`, also turned on for existing deployments) sends tool requests for reasoning-only models to the Responses API. Chat accepts `reasoning.mode` and `reasoning.summary`.
- **Failure Classification and Key Rotation** - Each failed attempt gets a `failure_class`. Credential and quota failures hold a key out for every model, and permanent per-key failures move to the next key even at `max_retries: 0`. Provider retry hints are exposed as `extra_fields.retry_after_ms`.
- **Routing Updates** - Routing targets accept `ttft_timeout_ms`, which hands a slow-to-start stream to the next fallback. When a rule or router rewrites the route, the original is returned in `routing_info.requested_provider`/`requested_model` and response headers. Every traced response carries `x-bifrost-request-id`.
- **Provider Objects Bound to the Creating Virtual Key** - Files, batches, videos, containers and cached contents can be read only through the virtual key that created them. Turn this off with `client.enforce_vk_object_ownership` (default `true`). File-based batches are checked against the key's model allowlist.
- **Security Hardening** - Several changes to defaults and status codes; review them before upgrading:
  - Passthrough routes forward only `POST` requests to allowlisted inference paths.
  - With dashboard auth off, browser requests to `/api/*` from unlisted origins return 403.
  - Secret references, private webhook targets, plugin endpoints and Vertex `auth_credentials` need real auth.
  - Re-enabling auth while it is off needs `current_password` or a `setup_token`.
  - Compressed bodies may expand at most 100 times.
- **Per-Virtual-Key Content Logging and Auto-Delete** - Virtual keys have a tri-state `disable_content_logging`, and `delete_after_expire` deletes a key once it expires. [Docs](https://docs.getbifrost.ai/features/governance/virtual-keys)
- **Global Proxy for All Outbound Traffic** - `proxy_config` can be set in config.json and Helm. With `enable_for_api`, MCP, catalog sync, OTel, webhooks and plugin downloads use it. With `enable_for_inference`, providers without their own proxy now actually send inference through it.
- **MCP Updates** - Tools can be refreshed on demand (`POST /api/mcp/client/{id}/refresh-tools`), and dropped sessions reconnect automatically. An evicted OAuth client can be re-registered. Upstream server `instructions` are forwarded and injected, with size caps. `mcp_oauth_private_allowlist` allows private OAuth servers. Rotating a virtual key revokes its MCP OAuth grants. Code mode runs on an in-process Starlark runtime with `code_mode_limits`. [Docs](https://docs.getbifrost.ai/mcp/code-mode)
- **Semantic Cache Updates** - Entries are scoped by identity (virtual key plus user), so expect a cold cache after upgrading. Responses with client tool calls are not cached unless `cache_tool_call_responses` is on. Lookups add `x-bifrost-cache-*` response headers. [Docs](https://docs.getbifrost.ai/features/semantic-caching)
- **Observability Updates** - New trace data and metric changes:
  - Root spans carry error attributes and an end-to-end TTFT.
  - OTel profiles can export raw payloads, drop listed attributes, and carry a `bifrost.cost.*` breakdown.
  - Metrics get an `app` label.
  - The root span uses the stable OTel HTTP attributes.
  - Tracing overhead is lower when no connector is attached. [Docs](https://docs.getbifrost.ai/features/observability/otel)
- **Response Headers Plugin Hook** - New `HTTPTransportResponseHeadersHook` lets plugins set headers on buffered and streaming responses. Custom Go plugins must add it (a no-op is fine).
- **Logs and Dashboard** - New views and controls:
  - Grouped logs collapse requests by `session_id`.
  - A Background jobs panel lists and cancels long jobs.
  - `object_storage_exclude_request_types` keeps chosen request types in the database instead of object storage.
  - Provider and model pickers are unified, with server-side search.
  - Entity pickers scroll infinitely.
- **Bifrost CLI** - The `bifrost` CLI covers the published API, with resource commands, `chat`, `infer`, `auth` (SSO included), `usage`, reversible `configure` for native agents, and table, JSON or YAML output.
- **Helm Chart 2.1.44** - Exposes the new config fields, `topologySpreadConstraints` and `extraContainers`.

## ⚙️ Upgrade Notes

These entries change a default, a status code, a response shape or a Go SDK type. The matching entries above describe each change in full.

- **Agent Gateway (A2A)** - optional; set `client.a2a_external_client_url` for push and stable card URLs, and `server.a2a_grpc_base_domain` + `server.a2a_grpc_port` (plus wildcard DNS) for gRPC. Custom `schemas.Tracer` implementations must add `ReleaseTrace`.
- **Warp AI Assistant (alpha)** - on by default in OSS; set `feature_flags.flags.warp.enabled: false` to keep it hidden.
- **Cloudflare Workers AI Provider** - the name `cloudflare` is reserved; migrate a custom provider named `cloudflare` with the dashboard dialog or recreate it with `cloudflare_key_config.account_id`.
- **Decisions API in OpenAI Shape** - map-form `/v1/decisions` bodies are deprecated (still served); update Go SDK code to the new `BifrostDecisionRequest` fields.
- **Decision Emulation Is Opt-In** - decisions on non-decision models return `unsupported_operation`; set `compat.convert_decision_to_responses: true` or send `x-bf-compat: ["convert_decision_to_responses"]` to keep emulation.
- **Multimodal Embeddings** - Go SDK `BifrostEmbeddingRequest.Input` is now `[]EmbeddingInputItem`; HTTP bodies are unchanged.
- **xAI Realtime** - refusal and content-filter stops are logged as `model_refusal` errors; exclude that error type from error-rate alerts if needed.
- **Web Search Priced per Request** - rename `search_context_cost_per_query` to `web_search_cost_per_request` in config.json overrides; read counts from `usage.tool_usage.web_search.num_requests`.
- **Compat: Route Reasoning-Only Models to Responses** - turned on for existing deployments; set `compat.force_reasoning_only_models_to_responses: false` to keep the old behavior.
- **Chat reasoning.mode and reasoning.summary** - the `/openai` chat route strips `reasoning.summary`; send it through `extra_params` there.
- **Failure Classification and Smarter Key Rotation** - a model missing on every key returns the provider's `404` instead of `502 upstream_credentials_exhausted`; update alerts on that error and on `fail_reason` values.
- **Gateway Request ID Header** - read the gateway request ID from `x-bifrost-request-id`; upstream `x-bifrost-*` headers are no longer forwarded.
- **Deprecated Models Hidden from Browsing** - add `include_deprecated=true` to `GET /api/models` to keep deprecated models.
- **Provider Objects Bound to the Creating Virtual Key** - set `client.enforce_vk_object_ownership: false` if virtual keys share files, batches, containers or cached contents.
- **File-Based Batches Under Model-Restricted Virtual Keys** - use a `*` model grant for OpenAI/Azure file batches, send an allowed `model` for Gemini/Vertex/Bedrock file batches, and never mix a file with inline `requests`.
- **Passthrough Route Hardening** - use passthrough only for `POST` inference paths with rooted paths, the route's own provider and one string `model` key.
- **Management API Refuses Unlisted Browser Origins** - add cross-origin browser apps to `client.allowed_origins` or enable dashboard auth.
- **Real Auth Required for Secret References and Private Targets** - enable dashboard auth or send `X-Bifrost-Setup-Token` for MCP `env.`/`vault.` references, private webhooks, plugin endpoints, Vertex `auth_credentials` and `DELETE /api/mcp-logs`.
- **Auth Config Changes Need Proof of Control** - send `auth_config.current_password` or `setup_token` when re-enabling auth or rotating admin credentials while auth is off.
- **Request Decompression Limits** - bodies expanding over 100x return `413`; send them uncompressed or raise `client.max_request_body_size_mb`.
- **Access Profiles for Teams, Business Units and Customers** - move config.json limits of governed entities and their keys onto the access profile.
- **Global Proxy in config.json and for All Outbound Traffic** - set `enable_for_inference: false` to keep inference direct, and list direct hosts in `proxy_config.no_proxy`.
- **Audit Logs: Omit IP Addresses** - make SIEM rules accept both audit `typeURI` values.
- **Attribution Context Keys Deprecated** - read attribution in custom plugins from `ctx.Grant()`, nil-checking every accessor. Do not swap a user, team, customer or business unit key for its Grant accessor one-for-one: a request made with a virtual key assigned to a user carries that user only on `BifrostContextKeyUserID`, so fall back to the key where the Grant has no answer.
- **MCP Client Target Validation at Connect Time** - register private MCP servers as an authenticated admin or in config.json, and use `http`, `sse` or `stdio` as `connection_type`.
- **MCP OAuth Server Hardening** - list remote OAuth callback URIs in `client.oauth2_server_config.allowed_redirect_uris` before upgrading.
- **Virtual Key Rotation Revokes MCP OAuth Grants** - re-authorize MCP clients after rotating their virtual key.
- **MCP Server Instructions** - bound injected instructions with `max_instructions_per_client`, `max_instructions_total` or per-client `max_instructions_length`.
- **Code Mode Execution Limits** - raise fields under `mcp.tool_manager_config.code_mode_limits` for scripts that exceed the new budgets.
- **Semantic Cache Scoped by Identity** - expect a cold cache; set `disable_identity_scoping: true` to share entries across identities.
- **Semantic Cache Skips Tool-Call Responses by Default** - set `cache_tool_call_responses: true` to keep caching them.
- **App Label on Metrics** - add the new `app` label to recording rules or alerts that match exact label sets.
- **OTel HTTP Semantic Conventions** - move dashboards to `http.request.method`, `http.response.status_code`, `http.route` and `url.path`; the span name and `http.url` drop the query string.
- **Response Headers Plugin Hook** - Go types implementing `HTTPTransportPlugin` must add `HTTPTransportResponseHeadersHook` (a no-op is fine).
- **Exclude Request Types from Object Storage** - only exclude request types whose content you do not need retained in object storage.
- **Helm Chart 2.1.44** - set `bifrost.client.oauth2ServerConfig.issuerUrl` when `mcpServerAuthMode` is `oauth` or `both`, or `helm template` fails.
