## Overview

Zhipu AI (智谱) is an **OpenAI-compatible provider** with a dedicated Bifrost provider implementation. Bifrost uses the shared OpenAI-compatible request and response converters, while preserving Zhipu-specific extra parameters such as `thinking`. Key characteristics:

- **OpenAI-compatible chat** - Chat Completions use `/chat/completions`
- **Streaming support** - Server-Sent Events for chat
- **Tool calling** - Function tools are passed through using the OpenAI-compatible schema
- **Reasoning support** - GLM thinking models return reasoning via `reasoning_content`
- **Responses API** - Supported by converting Responses requests to Chat Completions internally
- **Embeddings** - Text embeddings via `/embeddings` (`embedding-2`, `embedding-3`)
- **Image generation** - CogView models via `/images/generations`

### Supported Operations

| Operation | Non-Streaming | Streaming | Endpoint |
|-----------|---------------|-----------|----------|
| Chat Completions | ✅ | ✅ | `/chat/completions` |
| Responses API | ✅ | ✅ | `/chat/completions` |
| List Models | ✅ | - | `/models` |
| Embeddings | ✅ | ❌ | `/embeddings` |
| Image Generation | ✅ | ❌ | `/images/generations` |
| Text Completions | ❌ | ❌ | - |
| Speech (TTS) | ❌ | ❌ | - |
| Transcriptions (STT) | ❌ | ❌ | - |
| Files | ❌ | ❌ | - |
| Batch | ❌ | ❌ | - |

<Note>
**Unsupported Operations** (❌): Text Completions, Speech, Transcriptions, Files, Batch, cached content, containers, token counting, compaction, OCR, rerank, video, and passthrough are not offered through this provider. These return `UnsupportedOperationError`.
</Note>

## Setup & Configuration

Configure Zhipu AI as a provider. The default base URL is the China BigModel host. Override `network_config.base_url` to use the international Z.AI endpoint.

<Tabs>
<Tab title="Web UI">

1. Navigate to **Models** > **Model Providers**. Look for **Zhipu AI** under **Configured Providers**. If it is missing, click on **Add New Provider** and select **Zhipu AI**.
2. Click **Add Key** or edit an existing key.
3. Set a name for your key.
4. Paste your API key directly or use an environment variable (for example, `env.ZHIPU_API_KEY`).
5. Set **Allowed Models** to **All Models** (default) or the specific model allowlist you want this key to serve.
6. Save the provider configuration.

</Tab>

```json
{
  "providers": {
    "zhipu": {

        {

            "*"

    }
  }
}
```

# 1. Chat Completions

Zhipu's chat completions endpoint is OpenAI-compatible, so Bifrost delegates to the shared OpenAI implementation. For full parameter reference, message handling, tool conversion, and streaming behavior, see [OpenAI Chat Completions](/providers/supported-providers/openai#1-chat-completions).

Available chat models include `glm-5.3`, `glm-4.6`, and `glm-4.5-flash`. Call [List Models](#4-list-models) for the current catalog.

```bash
curl -X POST http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "zhipu/glm-4.6",
    "messages": [{"role": "user", "content": "你好"}]
  }'
```

### Reasoning

GLM thinking models return reasoning via `reasoning_content`. Enable thinking through extra parameters:

```json
{
  "model": "zhipu/glm-4.6",
  "messages": [{"role": "user", "content": "17 * 23 是多少？请逐步思考。"}],
  "thinking": { "type": "enabled" }
}
```

Bifrost enables passthrough extra parameters for Zhipu, so `thinking` and other Zhipu-specific fields are forwarded without being dropped. Assistant-message `reasoning_details` is stripped before replay; `reasoning_content` is kept on tool-call turns so GLM thinking models can continue the conversation.

# 2. Responses API

Bifrost converts the Responses API format to Chat Completions internally, then converts the response back:

```
BifrostResponsesRequest
  → ToChatRequest()
  → ChatCompletion
  → ToBifrostResponsesResponse()
```

Same parameter support as Chat Completions with response format differences (output items instead of message content).

```bash
curl -X POST http://localhost:8080/v1/responses \
  -H "Content-Type: application/json" \
  -d '{
    "model": "zhipu/glm-4.6",
    "input": "Hello"
  }'
```

# 3. Embeddings

Zhipu embeddings are OpenAI-compatible. Use `embedding-3` (recommended) or `embedding-2`.

```bash
curl -X POST http://localhost:8080/v1/embeddings \
  -H "Content-Type: application/json" \
  -d '{
    "model": "zhipu/embedding-3",
    "input": "智谱清言"
  }'
```

`embedding-3` accepts an optional `dimensions` extra parameter to control vector size.

```bash
curl http://localhost:8080/v1/models?provider=zhipu
```

# 5. Image Generation

Zhipu CogView models accept OpenAI-compatible image generation requests.

```bash
curl -X POST http://localhost:8080/v1/images/generations \
  -H "Content-Type: application/json" \
  -d '{
    "model": "zhipu/cogview-4",
    "prompt": "A red panda sitting on a mossy stone"
  }'
```

## Authentication

Zhipu uses `Authorization: Bearer <key>` on every endpoint.

Get an API key from [BigModel](https://open.bigmodel.cn/) (China) or [Z.AI](https://z.ai/) (international).

## Configuration

**HTTP Settings:**
- **Default base URL**: `https://open.bigmodel.cn/api/paas/v4`
- **International base URL**: `https://api.z.ai/api/paas/v4`
- **Chat endpoint**: `/chat/completions`
- **Embeddings endpoint**: `/embeddings`
- **Image endpoint**: `/images/generations`

## Caveats

<Accordion title="China vs international host">
**Severity**: Low
**Behavior**: The default base URL is BigModel (`open.bigmodel.cn`). Keys issued on Z.AI will not work against that host.
**Impact**: Set `network_config.base_url` to `https://api.z.ai/api/paas/v4` when using an international Z.AI key.
</Accordion>

<Accordion title="Thinking extra parameter">
**Severity**: Low
**Behavior**: GLM thinking is not mapped from OpenAI `reasoning_effort` on every model. Send `thinking: { "type": "enabled" }` through extra params when you want reasoning.
**Impact**: Requests without `thinking` use the model's default. Tool-call turns still replay `reasoning_content` when present.
</Accordion>

<Accordion title="Pricing uses the Z.AI catalog">
**Severity**: Low
**Behavior**: Request cost for `zhipu/<model>` is resolved from the datasheet's `zai` (Z.AI) rows. Chat models such as `glm-4.6` and `glm-5.3` pick up those rates automatically.
**Impact**: Logged and budgeted cost follows Z.AI international list prices, which can differ from China BigModel list prices. Embeddings (`embedding-3`) and CogView image models have no `zai` catalog row today, so their cost stays empty unless you add a [custom pricing](/providers/custom-pricing) override.
</Accordion>
