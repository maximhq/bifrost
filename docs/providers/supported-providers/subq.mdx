## Overview

Subq is an OpenAI-compatible provider at `https://api.subq.ai`. Bifrost registers it as `subq` and covers:

- **Chat Completions and Responses** for `subq-savant-1.4` (alias `subq-savant-latest`) — early access, 4M-token context, always reasons
- **Decisions** for `subq-snap-1.2` via Subq's System One endpoint (`/v1/systemone`)
- **Files** — upload, list, retrieve, and delete (`purpose=assistants` only; no content download)
- **List Models** — OpenAI list shape from `GET /v1/models`

### Supported Operations

| Operation | Non-Streaming | Streaming | Endpoint |
|-----------|---------------|-----------|----------|
| Chat Completions | ✅ | ✅ | `/v1/chat/completions` |
| Responses API | ✅ | ✅ | `/v1/responses` |
| Decisions | ✅ | - | `/v1/decisions` → `/v1/systemone` |
| List Models | ✅ | - | `/v1/models` |
| Files (upload/list/retrieve/delete) | ✅ | - | `/v1/files` |
| File Content | ❌ | - | - |
| Embeddings | ❌ | ❌ | - |
| Text Completions | ❌ | ❌ | - |
| Image / Audio / Batch / Containers | ❌ | ❌ | - |

<Note>
**Savant early access**: without org access enabled, Savant requests return `403 model_not_allowed`. Snap decisions and Files still work with a normal API key.

**Responses and images**: Subq's native Responses endpoint silently ignores image parts. When the input contains images, Bifrost falls back to Chat Completions so images still reach the model.

**Responses store**: Subq stores conversation state server-side by default. Send Bifrost's disable-store context (`BifrostContextKeyDisableStore`) to set `store: false`.
</Note>

## Setup & Configuration

Configure Subq with a bearer API key.

<Tabs>
<Tab title="Web UI">

1. Navigate to **Models** > **Model Providers**. Add **Subq** if it is missing.
2. Click **Add Key** or edit an existing key.
3. Paste your API key or use an environment variable (for example, `env.SUBQ_API_KEY`).
4. Set **Allowed Models** to **All Models** or the models this key should serve (`subq-savant-1.4`, `subq-snap-1.2`).
5. Save the provider configuration.

</Tab>
<Tab title="config.json">

```json
{
  "providers": {
    "subq": {
      "keys": [
        {
          "name": "subq-key-1",
          "value": "env.SUBQ_API_KEY",
          "models": ["*"],
          "weight": 1.0
        }
      ]
    }
  }
}
```

# 1. Chat Completions

Use `subq/subq-savant-1.4` (or `subq-savant-latest`). Bifrost rewrites requests to match Subq's Chat Completions contract:

| Client sends | Bifrost sends to Subq |
|--------------|------------------------|
| `temperature` other than `1` | Field omitted |
| `temperature: 1` | Kept |
| `max_completion_tokens` | Moved to `max_tokens` |
| `reasoning_effort: "none"` or `reasoning.enabled: false` | Dropped (Subq always reasons) |
| `reasoning_effort` `minimal` / `medium` / `xhigh` | Passed through for Subq to alias |
| `reasoning_effort` `low` / `high` / `max` | Passed through |
| Forced `tool_choice` (specific function) | Downgraded to `"auto"` |
| `tool_choice` `"auto"` / `"none"` | Kept |
| `stop` with more than 4 entries | Truncated to 4 |

<Warning>
Forced `tool_choice` cannot be honored on Subq. Bifrost downgrades it to `"auto"` rather than failing the request.
</Warning>

Reasoning content maps onto Bifrost's existing `message.reasoning` / delta reasoning fields.

---

# 2. Responses API

`POST /v1/responses` is native on Subq. Bifrost applies the same effort and tool-choice rules as Chat Completions: `reasoning.effort: "none"` is dropped, and forced/`required` `tool_choice` values are downgraded to `"auto"`. Temperature on Responses is accepted and ignored by Subq, so Bifrost leaves it alone.

When the Responses input includes images, Bifrost converts the request to Chat Completions and sets the Responses-to-chat fallback context key so the rest of the pipeline stays consistent.

---

# 3. Decisions

`POST /v1/decisions` with `subq/subq-snap-1.2` maps to Subq's System One API (`POST /v1/systemone`). Question types match Bifrost's Typesafe/System One shape (`predicate`/`noul`, `choice`, `score`).

Images must be inline `data:` URIs (up to 4). Bifrost converts them to Subq's `{mediaType, base64}` objects and rejects `http(s)` URLs and asset references with a 400 before the request leaves the gateway.

---

# 4. Files

Supported: upload, list, retrieve, delete. Bifrost forces `purpose=assistants` and sets the multipart Content-Type from the filename extension (Subq requires an explicit MIME type). File content download is not supported upstream and returns `UnsupportedOperationError`.
