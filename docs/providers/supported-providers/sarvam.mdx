## Overview

Sarvam AI is a voice and LLM provider focused on Indian languages (10 Indic languages + English). Bifrost supports both its text and voice workloads:
- **OpenAI-compatible chat (Token Factory v2)** - Chat completions delegate to the shared OpenAI implementation; Bifrost targets Sarvam's `/v2` API
- **Text-to-Speech (Bulbul)** - Custom mapping; Sarvam returns base64-encoded audio in a JSON `audios[]` array rather than raw binary
- **Speech-to-Text (Saaras/Saarika)** - Custom mapping; multipart upload with Sarvam-specific response fields (`transcript`, `timestamps`, `diarized_transcript`)
- **Decisions (Sarvam Prism)** - Custom mapping to Sarvam's System One API; returns calibrated probabilities for `noul`, `choice`, and `score` questions
- **Dual authentication** - Chat and decisions use `Authorization: Bearer`; voice endpoints use the `api-subscription-key` header

### Supported Operations

| Operation | Non-Streaming | Streaming | Endpoint |
|-----------|---------------|-----------|----------|
| Chat Completions | ✅ | ✅ | `/v2/chat/completions` |
| Responses API | ✅ | ✅ | `/v2/chat/completions` |
| Decisions | ✅ | - | `/v2/systemone` |
| Speech (TTS) | ✅ | ✅ | `/text-to-speech`, `/text-to-speech/stream` |
| Transcription (STT) | ✅ | ❌ | `/speech-to-text` |
| List Models | ✅ | - | `/v2/models` |
| Text Completions | ❌ | ❌ | - |
| Embeddings | ❌ | ❌ | - |

<Note>
**Unsupported Operations** (❌): Text Completions, Embeddings, Images, Files, Batch, and streaming transcription are not offered by the upstream Sarvam API. These return `UnsupportedOperationError`.
</Note>

## Setup & Configuration

Configure Sarvam AI as a provider. The same API key works for both chat and voice.

<Tabs>
<Tab title="Web UI">

1. Navigate to **Models** > **Model Providers**. Look for **Sarvam AI** under **Configured Providers**. If it is missing, click on **Add New Provider** and select **Sarvam AI**.
2. Click **Add Key** or edit an existing key.
3. Set a name for your key.
4. Paste your API key directly or use an environment variable (for example, `env.SARVAM_API_KEY`).
5. Set **Allowed Models** to **All Models** (default) or the specific model allowlist you want this key to serve.
6. Save the provider configuration.

# 1. Chat Completions

Sarvam's Token Factory v2 chat completions endpoint is OpenAI-compatible, so Bifrost delegates to the shared OpenAI implementation. For full parameter reference, message handling, tool conversion, and streaming behavior, see [OpenAI Chat Completions](/providers/supported-providers/openai#1-chat-completions).

### Available Models

| Model | Context Window | Notes |
|-------|----------------|-------|
| `sarvam-105b` | 128,000 | Sarvam's flagship Indic model; reasoning on by default |
| `sarvam-105b-conversations` | 32,000 | Conversation-tuned variant of `sarvam-105b`; no reasoning |
| `glm5.3` | 1,048,576 | Reasoning model |
| `glm5.3-flash` | 1,048,576 | Faster, lower-cost reasoning model |
| `gemma4` | 262,144 | Google Gemma 4; reasoning available, off by default |
| `deepseekv4.1-flash-1017` | 1,048,576 | DeepSeek V4.1 Flash; reasoning model |

```bash
curl -X POST http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "sarvam/glm5.3-flash",
    "messages": [{"role": "user", "content": "Namaste!"}]
  }'
```

<Note>
**Reasoning models.** `sarvam-105b`, `glm5.3`, `glm5.3-flash`, and `deepseekv4.1-flash-1017` reason by default; `gemma4` supports reasoning but leaves it off unless requested. Reasoning tokens count toward `max_tokens`; with a small budget the response can return empty `content` and `finish_reason: "length"`. Use at least 1024 output tokens for reasoning models. Set `reasoning_effort` to `low` or `high`; GLM models reject `max` (it is mapped to `xhigh` upstream).
</Note>

# 2. Responses API

Bifrost converts the Responses API format to Chat Completions internally, then converts the response back:

```
BifrostResponsesRequest
  → ToChatRequest()
  → ChatCompletion
  → ToBifrostResponsesResponse()
```

Same parameter support as Chat Completions with response format differences (output items instead of message content). Sarvam rejects `previous_response_id`, `conversation`, and `background: true`; use `reasoning.effort` of `low` or `high`.

# 3. Decisions (Sarvam Prism)

Sarvam Prism is a decision model served by `POST /v2/systemone`. It returns calibrated probabilities for typed questions instead of text, so it is reached through Bifrost's `/v1/decisions` route, not chat.

| Bifrost question type | Sarvam question type | Answer |
|---|---|---|
| `predicate` | `noul` | `probability` in [0,1] |
| `choice` | `choice` | the option with the highest probability |
| `score` | `score` | probability-weighted level index |

Limits: 32,768 tokens per question (state + question + options), 2-255 options per `choice`, and 2-10 levels per `score`. Images, box questions, and streaming are not supported; `temperature`, `max_tokens`, and `stream` are refused. Each request must finish within 60 seconds.

```bash
curl -X POST http://localhost:8080/v1/decisions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "sarvam/sarvam-prism",
    "input": "Customer: I was double charged and nobody replied.",
    "questions": [
      {"type": "predicate", "name": "is_frustrated", "instructions": "Is the customer frustrated?"}
    ]
  }'
```

# 4. Speech (Text-to-Speech, Bulbul)

Sarvam's TTS endpoint is **not** OpenAI-compatible: it returns JSON with base64-encoded audio in an `audios[]` array, which Bifrost decodes into raw audio bytes. The streaming endpoint returns raw binary audio chunks, which Bifrost forwards as speech-audio deltas.

### Parameter Mapping

| Bifrost field | Sarvam field | Notes |
|---------------|--------------|-------|
| `input` | `text` | Text to synthesize (required) |
| `voice` | `speaker` | e.g. `shubh` (v3), `anushka` (v2) |
| `speed` | `pace` | Playback speed |
| `language_code` | `target_language_code` | BCP-47 Indic code, e.g. `hi-IN` (**required**) |

Sarvam-specific fields are read from `ExtraParams`: `pitch`, `loudness`, `temperature`, `speech_sample_rate`, `output_audio_codec`, `enable_preprocessing`, `dict_id`, `enable_cached_responses`.

```bash
curl -X POST http://localhost:8080/v1/audio/speech \
  -H "Content-Type: application/json" \
  -d '{
    "model": "sarvam/bulbul:v3",
    "input": "Namaste, aap kaise hain?",
    "voice": "shubh",
    "language_code": "hi-IN"
  }' --output speech.wav
```

<Note>
`target_language_code` is required by Sarvam. Pass it as `language_code` or as an extra field; without it the request is rejected. `bulbul:v2` is deprecated upstream; use `bulbul:v3`.
</Note>

# 5. Transcription (Speech-to-Text, Saaras/Saarika)

Sarvam's STT endpoint accepts a multipart audio upload and returns a custom response shape that Bifrost maps onto its standard transcription format.

### Response Mapping

| Sarvam field | Bifrost field | Notes |
|--------------|---------------|-------|
| `transcript` | `text` | Transcribed text |
| `language_code` | `language` | Detected BCP-47 language |
| `timestamps` (parallel arrays) | `words[]` | Flattened into per-word `{word, start, end}` |
| `diarized_transcript.entries` | diarized segments | Speaker-attributed segments |

Request fields `mode` and `input_audio_codec` are read from `ExtraParams`; `language` maps to Sarvam's `language_code`.

<Note>
`timestamps` and `diarized_transcript` are only returned by Sarvam's **Batch** speech-to-text API; the synchronous `/speech-to-text` endpoint used here returns `transcript` and `language_code`. Bifrost maps `words`/diarized segments when present, so the standard path typically populates only `text` and `language`.
</Note>

```bash
curl -X POST http://localhost:8080/v1/audio/transcriptions \
  -F "model=sarvam/saaras:v3" \
  -F "file=@speech.wav"
```

## Authentication

Sarvam uses different authentication for chat and voice, but the **same API key** works for both:

- **Chat / Responses**: `Authorization: Bearer <key>`
- **Speech / Transcription**: `api-subscription-key: <key>`

Bifrost applies the correct header per operation automatically.

## Configuration

**HTTP Settings:**
- **Base URL**: `https://api.sarvam.ai` (default)
- **Chat endpoint**: `/v2/chat/completions`
- **Decisions endpoint**: `/v2/systemone`
- **Models endpoint**: `/v2/models`
- **Voice endpoints**: `/text-to-speech`, `/text-to-speech/stream`, `/speech-to-text`

## Caveats

<Accordion title="Voice is not OpenAI-compatible">
**Severity**: Low
**Behavior**: TTS returns base64 JSON (not raw audio) and STT returns Indic-specific fields.
**Impact**: Handled by Bifrost's custom mapping; no action needed by callers beyond passing `target_language_code` for TTS.
</Accordion>

<Accordion title="No streaming for transcription">
**Severity**: Low
**Behavior**: Sarvam does not offer streaming speech-to-text.
**Impact**: `TranscriptionStream` returns `UnsupportedOperationError`. TTS streaming is supported via `/text-to-speech/stream`.
</Accordion>

<Accordion title="Reasoning models need a larger output budget">
**Severity**: Medium
**Behavior**: Reasoning tokens count toward `max_tokens`. A small cap can leave `content` empty with `finish_reason: "length"`.
**Impact**: Use at least 1024 output tokens for `sarvam-105b`, `glm5.3`, `glm5.3-flash`, and `deepseekv4.1-flash-1017`, or set `reasoning_effort` to `low`.
</Accordion>

<Accordion title="Prism is a decision model, not a chat model">
**Severity**: Low
**Behavior**: `sarvam-prism` is served by `POST /v2/systemone` and returns probabilities, not text. It is reachable through `/v1/decisions`, not `/v1/chat/completions`; a chat request for it fails upstream.
**Impact**: Use the Decisions route. To hide it from the chat model list, add `sarvam-prism` to the key's `blacklisted_models`.
</Accordion>

<Accordion title="Model-specific parameter limits">
**Severity**: Low
**Behavior**: `n > 1` is not supported. `stop` accepts at most 4 sequences on `sarvam-105b` and `glm5.3`. `logprobs` is rejected on `glm5.3`. GLM models reject `reasoning_effort: "max"`.
**Impact**: Requests outside these limits return an upstream 400 error.
</Accordion>
