## Overview

Azure is a cloud provider offering access to OpenAI and Anthropic models through the Azure OpenAI Service. Bifrost performs conversions including:

- **Deployment mapping** - Model identifiers mapped to Azure deployment IDs with version handling
- **Authentication modes** - API key, Entra ID (Service Principal), or Managed Identity (DefaultAzureCredential) with
  automatic environment detection
- **Model routing** - Automatic provider detection (OpenAI vs Anthropic) based on deployment
- **v1 API** - Uses `/openai/v1/` endpoints for all operations except transcription, which uses the classic `/openai/deployments/{model}/audio/transcriptions?api-version=...` path as the v1 equivalent is not yet available
- **Custom endpoints** - Full control over Azure endpoint configuration
- **Multi-model support** - Unified interface for OpenAI, Anthropic (via Azure), and Gemini models
- **Request/response pass-through** - Support for raw request/response bodies for advanced use cases

### Supported Operations

| Operation        | Non-Streaming | Streaming | Endpoint                        |
| ---------------- | ------------- | --------- | ------------------------------- |
| Chat Completions | ✅            | ✅        | `/openai/v1/chat/completions`   |
| Responses API    | ✅            | ✅        | `/openai/v1/responses`          |
| Embeddings       | ✅            | -         | `/openai/v1/embeddings`         |
| Files            | ✅            | -         | `/openai/v1/files`              |
| List Models      | ✅            | -         | `/openai/v1/models`             |
| Image Generation | ✅            | ✅        | `/openai/v1/images/generations` |
| Image Edit       | ✅            | ✅        | `/openai/v1/images/edits`       |
| Video Generation | ✅            | -         | `/openai/v1/videos`             |
| Context Compaction | ✅          | -         | `/openai/v1/responses/compact`  |
| Decisions        | ✅            | -         | `/openai/v1/decisions` (`gpt-6-luna`), `/providers/microsoft/v1/systemone` (`Microsoft-Decision-1`) |
| GPT Live         | -             | ✅        | `/openai/v1/live/sessions`      |
| Image Variation  | ❌            | ❌        | -                               |
| Batch            | ❌            | ❌        | -                               |
| Text Completions | ❌            | ❌        | -                               |
| Speech (TTS)     | ✅            | ✅        | `/openai/v1/audio/speech`, or `/tts/cognitiveservices/v1` for [Azure AI Speech](#11-azure-ai-speech) |
| Transcription    | ✅            | -         | `/openai/deployments/{model}/audio/transcriptions`, or `/speechtotext/transcriptions:transcribe` for [Azure AI Speech](#11-azure-ai-speech) |

<Note>
  **Azure-specific**: Batch operations and Text Completions are not supported by
  Azure OpenAI Service. Responses API is available for both OpenAI and Anthropic models.
</Note>

## Setup & Configuration

Azure requires an endpoint URL, deployment mappings, and authentication configuration. Three authentication methods are supported.

<Note>
  The `aliases` field (mapping model names to Azure deployment IDs) requires
  **v1.5.0-prerelease2 or later**. On v1.4.x, use `deployments` inside
  `azure_key_config` instead - see the [v1.5.0 Migration
  Guide](/migration-guides/v1.5.0#breaking-change-9-provider-deployments-removed-migrate-to-aliases)
  for details.
</Note>

### 1. Default Credential (System Identity)

Leave `value` and all Entra ID fields empty. Bifrost calls `azidentity.NewDefaultAzureCredential(nil)`, which tries credential sources in this order:

1. Environment variables (`AZURE_CLIENT_ID` + `AZURE_CLIENT_SECRET` + `AZURE_TENANT_ID`, or certificate/username variants)
2. Workload Identity (AKS with Workload Identity Federation)
3. Managed Identity (Azure VMs, App Service, AKS, Container Instances)
4. Azure CLI (`az login`)
5. Azure Developer CLI (`azd auth login`)

This covers managed identity on Azure infrastructure, workload identity in AKS, and local development via `az login`. No credentials need to be stored or rotated.

1. Navigate to **"Model Providers"** → **"Configurations"** → **"Azure"**
2. Click **"Add Key"** (or edit an existing key)
3. Under **Authentication Method**, select **"Default Credential"**
4. Set **Endpoint**: Your Azure OpenAI resource URL (e.g., `https://your-org.openai.azure.com`)
5. Configure **Aliases**: Map model names to deployment IDs (e.g., `gpt-4o` → `my-gpt4o-deployment`)
6. Save

Ensure the appropriate credential source is available - a managed identity attached to the Azure resource, `AZURE_CLIENT_ID`/`AZURE_CLIENT_SECRET`/`AZURE_TENANT_ID` env vars, or `az login` for local development.

## Beta Headers

For Anthropic models on Azure, Bifrost validates `anthropic-beta` headers and drops unsupported headers from the request. Azure supports most Anthropic beta features.

**Supported**: `computer-use-*`, `structured-outputs-*`, `advanced-tool-use-*`, `mcp-client-*`, `prompt-caching-scope-*`, `compact-*`, `context-management-*`, `files-api-*`, `interleaved-thinking-*`, `skills-*`, `context-1m-*`, `redact-thinking-*`

**Not supported**: `fast-mode-*`

You can override these defaults per provider via the **Beta Headers** tab in provider configuration or via [`beta_header_overrides`](/quickstart/gateway/provider-configuration#beta-header-overrides). See the full support matrix in the [Anthropic provider docs](/providers/supported-providers/anthropic#beta-headers).

# 1. Chat Completions

## Request Parameters

### Core Parameter Mapping

| Parameter               | Azure Handling            | Notes                                                |
| ----------------------- | ------------------------- | ---------------------------------------------------- |
| `model`                 | Mapped to `deployment_id` | Supports version matching and base model matching    |
| `max_completion_tokens` | Direct pass-through       | OpenAI models only                                   |
| `temperature`, `top_p`  | Direct pass-through       | Same across all models                               |
| All other params        | Model-specific conversion | Converted per underlying provider (OpenAI/Anthropic) |

### Key Configuration

Azure supports three authentication methods: **Managed Identity** (DefaultAzureCredential), **Entra ID** (Service Principal), and **Direct** (API Key). Precedence: Entra ID (if configured) → API key (if `value` set) → DefaultAzureCredential.

#### Managed Identity / DefaultAzureCredential

If no API key and no Entra ID credentials are provided, Bifrost automatically uses `DefaultAzureCredential`, which
detects the auth environment.

```json
{
  "aliases": {
    "gpt-4": "my-gpt4-deployment"
  },
  "azure_key_config": {
    "endpoint": "https://your-org.openai.azure.com"
  }
}
```

#### Azure Entra ID (Service Principal)

If you set `client_id`, `client_secret`, and `tenant_id`, Azure Entra ID authentication will be used with priority over API key authentication.

```json
{
  "aliases": {
    "gpt-4": "my-gpt4-deployment",
    "gpt-4-turbo": "my-gpt4-turbo-deployment",
    "claude-3": "my-claude-deployment"
  },
  "azure_key_config": {
    "endpoint": "https://your-org.openai.azure.com",
    "client_id": "your-client-id",
    "client_secret": "your-client-secret",
    "tenant_id": "your-tenant-id",
    "scopes": ["https://cognitiveservices.azure.com/.default"]
  }
}
```

**Required Azure Roles**:

- For OpenAI models: `Cognitive Services OpenAI User`
- For Anthropic models: `Cognitive Services AI Services User`

#### Direct Authentication (API Key)

```json
{
  "value": "your-azure-api-key",
  "aliases": {
    "gpt-4": "my-gpt4-deployment",
    "gpt-4-turbo": "my-gpt4-turbo-deployment",
    "claude-3": "my-claude-deployment"
  },
  "azure_key_config": {
    "endpoint": "https://your-org.openai.azure.com"
  }
}
```

**Configuration Details**:

- `endpoint` - Azure OpenAI resource endpoint (required)
- `client_id` - Azure Entra ID client ID (optional, for Service Principal auth)
- `client_secret` - Azure Entra ID client secret (optional, for Service Principal auth)
- `tenant_id` - Azure Entra ID tenant ID (optional, for Service Principal auth)
- `scopes` - OAuth scopes for token requests (default: `["https://cognitiveservices.azure.com/.default"]`)
- `use_speech_endpoints` - Send speech and transcription requests to Azure AI Speech (optional, default `false`; an alias can override it)
- `use_voice_live_endpoints` - Send realtime WebSocket sessions to Azure Voice Live (optional, default `false`; an alias can override it)
- `aliases` - Map of model names to Azure deployment IDs (optional, set at key level)
- `allowed_models` - List of allowed models to use from this key (optional)

### Deployment Selection

Deployments can be specified at three levels (in order of precedence):

1. **Per-request** (highest priority)

   ```json
   { "deployment": "custom-deployment" }
   ```

2. **Key configuration**

   ```json
   { "aliases": { "gpt-4": "my-gpt4-deployment" } }
   ```

3. **Model name** (lowest priority, if no deployment specified)
   Model name is used as deployment ID directly

## OpenAI Models

When using OpenAI models (GPT-4, GPT-4 Turbo, GPT-3.5-Turbo, etc.), Bifrost passes through OpenAI-compatible parameters directly.

### Parameter Mapping for OpenAI

All OpenAI-standard parameters are supported. Refer to [OpenAI documentation](/providers/supported-providers/openai) for detailed conversion details.

## Anthropic Models

When using Anthropic models through Azure (Claude 3 family), Bifrost converts requests to Anthropic format.

### Parameter Mapping for Anthropic

All Anthropic-standard parameters are supported with special handling:

- **Reasoning/Thinking**: `reasoning` parameters converted to Anthropic's `thinking` structure
- **System messages**: Extracted and placed in separate `system` field
- **Tool message grouping**: Consecutive tool messages merged

Refer to [Anthropic documentation](/providers/supported-providers/anthropic) for detailed conversion details.

### Special Notes for Azure + Anthropic

- API version automatically set to `2023-06-01` for Anthropic models
- Endpoints use `/anthropic/v1/` paths internally
- Authentication uses `x-api-key` header for Anthropic models
- Minimum reasoning budget: 1024 tokens

## Streaming

Streaming uses OpenAI or Anthropic format depending on model type:

- **OpenAI models**: Standard OpenAI streaming with `chat.completion.chunk` events
- **Anthropic models**: Anthropic streaming format with content blocks

# 2. Responses API

The Responses API is available for both OpenAI and Anthropic models on Azure using the `/openai/v1/responses` endpoint.

## Request Parameters

### Core Parameter Mapping

| Parameter           | Azure Handling               | Notes                             |
| ------------------- | ---------------------------- | --------------------------------- |
| `instructions`      | Becomes system message       | Model-specific conversion         |
| `input`             | Converted to user message(s) | String or array support           |
| `max_output_tokens` | Model-specific field mapping | OpenAI vs Anthropic conversion    |
| All other params    | Model-specific conversion    | Converted per underlying provider |

### OpenAI Models

For OpenAI models (GPT-4, etc.), conversion follows OpenAI's Responses API format.

### Anthropic Models

For Anthropic models (Claude, etc.), conversion follows Anthropic's message format:

- `instructions` becomes system message
- `reasoning` mapped to `thinking` structure

# 10. Decisions

Two kinds of Azure deployment answer [`/v1/decisions`](/quickstart/gateway/decisions), each on its own endpoint and in its own format:

| Model | Azure endpoint | Format |
|-------|----------------|--------|
| [`gpt-6-luna`](https://learn.microsoft.com/en-us/azure/foundry/openai/how-to/decisions) | `/openai/v1/decisions` | OpenAI's decisions format |
| [`Microsoft-Decision-1`](https://learn.microsoft.com/en-us/azure/foundry/foundry-models/how-to/use-foundry-models-microsoft-decision) | `/providers/microsoft/v1/systemone` | TypeSafe's System One format |

Bifrost picks the endpoint by model name: a deployment of the `gpt-6-luna` family goes to `/openai/v1/decisions`, and any other deployment to `/providers/microsoft/v1/systemone`. Azure sends the deployment name as the model, so when your deployment is named differently, map the model name to it with a key alias. Bifrost then recognizes the deployment by the alias name:

```json
{ "aliases": { "gpt-6-luna": "my-luna-deployment", "Microsoft-Decision-1": "my-decision-deployment" } }
```

## gpt-6-luna

```bash
curl http://localhost:8080/v1/decisions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "azure/gpt-6-luna",
    "input": "Customer message: I was double charged and nobody replied to my two emails.",
    "questions": [
      { "type": "predicate", "name": "is_frustrated", "instructions": "Is the customer frustrated?" },
      { "type": "choice", "name": "category", "instructions": "Pick the ticket category",
        "choices": [ { "value": "billing" }, { "value": "bug" }, { "value": "other" } ] }
    ]
  }'
```

Bifrost calls `POST {endpoint}/openai/v1/decisions` in OpenAI's decisions format, so requests and answers map as on [OpenAI](/providers/supported-providers/openai#15-decisions), including `input_image` parts (a base64 data URL or a public HTTPS URL). Authentication (API key, Entra ID, or managed identity) is applied as for every other Azure call, and no `api-version` is sent. Azure is rolling the endpoint out by region; a deployment in a region without it returns Azure's own error. See Microsoft's [Decisions API guide](https://learn.microsoft.com/en-us/azure/foundry/openai/how-to/decisions) for availability and limits.

## Microsoft-Decision-1

```bash
curl http://localhost:8080/v1/decisions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "azure/Microsoft-Decision-1",
    "input": "Customer message: I was double charged and nobody replied to my two emails.",
    "questions": [
      { "type": "predicate", "name": "is_frustrated", "instructions": "Is the customer frustrated?" }
    ]
  }'
```

Bifrost calls `POST {endpoint}/providers/microsoft/v1/systemone`, which uses TypeSafe's System One format, so questions are converted as on [TypeSafe](/providers/supported-providers/typesafe#field-mapping-reference). Authentication (API key, Entra ID, or managed identity) is applied as for every other Azure call, and no `api-version` is sent. Differences from TypeSafe:

- **Text only.** An `input_image` part is rejected by Bifrost with a `400`; the model would otherwise read it as text.
- **Strict top-level fields.** An extra field forwarded with `x-bf-passthrough-extra-params` comes back as Azure's `400` (`Unrecognized request argument supplied`).
- **Limits.** Choice questions take 2-255 options and score questions 2-10 levels; the context window is 32,768 tokens.
- **No response `id`.** Azure's `x-request-id` is in `extra_fields.provider_response_headers`.

Bifrost does not otherwise gate decisions on Azure by model name: a deployment that serves neither endpoint returns Azure's own error. With [`convert_decision_to_responses`](/features/compat-plugin#4-decision-to-responses-emulation) on, `gpt-6-luna` and `Microsoft-Decision-1` are still served natively. The [complexity router](/features/complexity-router#choosing-the-decision-model) can use `Microsoft-Decision-1` as its classifier.

A decision is priced from the model catalog: at the model's decision rates where it lists them, otherwise at its chat rates. A model the catalog does not list is priced at $0; add a [pricing override](/providers/custom-pricing) for the Decisions request type to bill it.

# 11. Azure AI Speech

`use_speech_endpoints` sends speech and transcription requests to [Azure AI Speech](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/) instead of an Azure OpenAI deployment, on the same key and endpoint. Set it in `azure_key_config` to route every audio request on the key, or on an alias to route one model. An alias value wins over the key's in both directions. Other requests on the key, such as chat, still go to Azure OpenAI.

The endpoint must be a Foundry (AI Services) resource or a Speech resource with a custom domain. Both `*.openai.azure.com` and `*.cognitiveservices.azure.com` work.

An API key is sent as `Ocp-Apim-Subscription-Key`. Entra ID and managed identity send a bearer token, as for every other Azure call. A key with an explicit `models` list must list the alias names it serves.

```json
{
  "name": "azure-key",
  "value": "env.AZURE_API_KEY",
  "models": ["*"],
  "azure_key_config": { "endpoint": "env.AZURE_ENDPOINT" },
  "aliases": {
    "mai-voice": { "model_id": "MAI-Voice-2.1-Flash", "use_speech_endpoints": true },
    "fast-stt": { "model_id": "fast-transcription", "use_speech_endpoints": true }
  }
}
```

The model ID, which is the alias `model_id` or the requested model on a key with `use_speech_endpoints`, picks the voice or transcription mode.

## Text to speech

**Endpoint**: `POST /v1/audio/speech`, sent to `{endpoint}/tts/cognitiveservices/v1` as SSML

| Model ID | Voice sent to Azure |
| --- | --- |
| `neural` | `voice` as is, such as `en-US-JennyNeural` |
| A voice suffix, such as `DragonHDLatestNeural` or `MAI-Voice-2.1-Flash` | `{voice}:{suffix}`, such as `en-US-Harper:MAI-Voice-2.1-Flash` |

A voice that already contains `:` is sent as is. OpenAI voice names such as `alloy` are not Azure voices and get a `400`.

| Parameter | Azure SSML |
| --- | --- |
| `input` | Escaped voice text. An input that starts with `<speak` is sent as the whole SSML document. |
| `speed` | `<prosody rate="{speed}">` |
| `language_code` | `xml:lang` on `<speak>`, `en-US` when not set |
| `style`, `styledegree`, `role` | `<mstts:express-as>` |
| `response_format` | `mp3` (default), `opus`, `wav` and `pcm` map to 24 kHz formats; `aac` and `flac` fall back to mp3; any other value is sent as the `X-Microsoft-OutputFormat` name |
| `instructions` | Dropped |

`stream_format: "sse"` streams the audio as Azure synthesizes it. `usage.input_chars` counts characters as Azure bills them: the whole SSML except the `<speak>` and `<voice>` tags, with each Chinese character counted twice. Markup Bifrost adds, such as `<prosody>`, is billed.

```bash
curl http://localhost:8080/v1/audio/speech \
  -H "Content-Type: application/json" \
  -d '{
    "model": "azure/mai-voice",
    "voice": "en-US-Harper",
    "input": "Your order shipped.",
    "speed": 1.2
  }' --output speech.mp3
```

## Speech to text

**Endpoint**: `POST /v1/audio/transcriptions`, sent to `{endpoint}/speechtotext/transcriptions:transcribe?api-version=2025-10-15` as an `audio` part and a JSON `definition`

| Model ID | Azure mode |
| --- | --- |
| `fast-transcription` | Fast transcription |
| `llm-speech` | LLM Speech (`enhancedMode.task`) |
| Any other, such as `MAI-Transcribe-2` | `enhancedMode.model` set to the model ID |

LLM Speech and MAI-Transcribe are available only in [some regions](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/regions?tabs=llmspeech); other regions answer `400` with `Enhanced mode is currently not supported yet.`

| Field | Azure definition |
| --- | --- |
| `language` | `locales`. `fast-transcription` needs a full locale such as `en-US`; a bare code such as `en` is dropped and Azure detects the language. |
| `prompt` | `enhancedMode.prompt` on `llm-speech`; dropped otherwise |
| `target_language` | `llm-speech` translates into it |
| `response_format: "verbose_json"` | `modelOptions.timestamps: "word"` on MAI-Transcribe |
| `response_format: "diarized_json"`, `diarization`, `max_speakers` | `diarization` |
| `channels`, `phrases` | `channels`, `phraseList.phrases`. Pass a comma-separated value in a multipart form. |
| `profanity_filter_mode`, `transcribe_style` | `profanityFilterMode`, `modelOptions.transcribeStyle` |

The response carries `text`, `duration`, `language`, `segments` (speaker-labelled when diarized) and `words`. `usage.seconds` is the duration rounded up to the second, which is what Azure meters.

```bash
curl http://localhost:8080/v1/audio/transcriptions \
  -F model=azure/fast-stt \
  -F file=@call.wav \
  -F language=en-US \
  -F diarization=true
```

Until the model catalog lists rates for these model IDs, Bifrost reports their cost as $0 while Azure still bills the usage; add a [pricing override](/providers/custom-pricing) to track it.

# 12. Azure Voice Live

`use_voice_live_endpoints` sends realtime WebSocket sessions to [Azure Voice Live](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/voice-live) instead of Azure OpenAI, on the same key and endpoint. Set it in `azure_key_config` for every realtime session on the key, or on an alias for one model. An alias value wins over the key's in both directions. Other requests on the key still go to Azure OpenAI.

**Endpoint**: `/v1/realtime` (WebSocket), sent to `{endpoint}/voice-live/realtime?api-version=2026-04-10&model={model ID}` with the key's API key or Entra token. An alias `api_version` replaces the default version.

```json
"aliases": {
  "gpt-realtime-vl": { "model_id": "gpt-realtime", "use_voice_live_endpoints": true }
}
```

The model ID is a Voice Live model such as `gpt-realtime`, `gpt-4.1` or `phi4-mm-realtime`, which needs no deployment. Connect to `ws://localhost:8080/v1/realtime?model=azure/gpt-realtime-vl`. Events pass through as Voice Live sends them, including object voices such as `{"name": "en-US-Ava:DragonHDLatestNeural", "type": "azure-standard"}`, `azure_semantic_vad`, noise suppression, word timestamps, visemes and `session.avatar.connect`.

- WebRTC (`/v1/realtime/calls`) and client secrets (`/v1/realtime/client_secrets`) answer `400`: Voice Live signals WebRTC over its own WebSocket and reports usage on the browser's data channel.
- A realtime `intent` answers `400`.
- Turns are priced at the Azure OpenAI rates for the same model name until the model catalog lists Voice Live rates.

# 13. GPT Live

Azure serves [GPT-Live](https://learn.microsoft.com/en-us/azure/foundry/openai/concepts/gpt-live) on OpenAI's wire protocol, so a session's events, delegation, billing and log row are the same as on OpenAI. Open the session on `/v1/live/sessions` (a WebSocket, or a `POST` with an SDP offer for WebRTC) with the `azure/` prefix on the voice model:

```json
{
  "type": "session.start",
  "session": {
    "model": "azure/gpt-live-1",
    "delegation": { "type": "responses", "responses": { "model": "gpt-5.5" } }
  }
}
```

A voice model without a prefix runs on Azure when the request comes from the Azure OpenAI SDK, and on OpenAI otherwise on `/openai/v1/live/sessions`, the same provider the session's attach and content routes default to.

Bifrost connects to `{endpoint}/openai/v1/live/sessions` with the key's API key or Entra ID token. Both `session.model` and `delegation.responses.model` are deployment names on Azure, and Bifrost maps each through the key's aliases. Azure runs the backend on the voice deployment's resource, so one key must serve both models, and the key's `endpoint` is used even when an alias sets its own.

- **Sidebands**: `/v1/live/sessions/{session_id}/attach` and `/openai/v1/live/sessions/{session_id}/attach` take `?provider=azure` or the `x-model-provider: azure` header, and the Azure OpenAI SDK's user agent selects Azure too. Without any of these, the route uses OpenAI when OpenAI is configured.
- **Browser permissions**: Azure rejects `session.client` on WebRTC create, so Bifrost drops it upstream and applies `allowed_client_events` and `allowed_server_events` itself on the browser's data channel. A browser event outside the list gets OpenAI's `event_not_allowed` error and never reaches Azure. Sidebands are not restricted.
- **Recordings**: `/v1/live/sessions/{session_id}/content` answers `400 unsupported_operation`. Azure does not store GPT-Live sessions yet and rejects `session.store`.
- **Pricing overrides** match the deployment name Bifrost sends, not the alias.
