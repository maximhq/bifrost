## Overview

CoreWeave serves open-weight models through W&B Inference, an OpenAI-compatible vLLM gateway at `https://api.inference.wandb.ai/v1`. Bifrost uses the shared OpenAI converters against the gateway's own endpoints:

- **Chat** - `/chat/completions`, with SSE streaming
- **Responses** - `/responses` for non-streaming; streaming goes through Chat Completions
- **Tools** - OpenAI function tools, including parallel calls
- **Reasoning** - returned in the message `reasoning` field
- **Vision** - `image_url` parts as URLs or base64 data URIs
- **Text completions** - `/completions`, with SSE streaming
- **Extra params** - passed through untouched

### Supported Operations

| Operation | Non-Streaming | Streaming | Endpoint |
|-----------|---------------|-----------|----------|
| Chat Completions | ✅ | ✅ | `/chat/completions` |
| Responses API | ✅ | ✅ | `/responses` (non-streaming), `/chat/completions` (streaming) |
| Text Completions | ✅ | ✅ | `/completions` |
| List Models | ✅ | - | `/models` |
| Embeddings | ❌ | ❌ | - |
| Image Generation | ❌ | ❌ | - |
| Speech (TTS) | ❌ | ❌ | - |
| Transcriptions (STT) | ❌ | ❌ | - |
| Files | ❌ | ❌ | - |
| Batch | ❌ | ❌ | - |

<Note>
W&B Inference does not offer embeddings, images, speech, transcription, files, or batch. Bifrost returns `UnsupportedOperationError` for them.
</Note>

## Setup & Configuration

Create a personal or service-account API key in [W&B settings](https://wandb.ai/settings), then configure CoreWeave as a provider.

<Tabs>
<Tab title="Web UI">

1. Navigate to **Models** > **Model Providers**. Look for **CoreWeave** under **Configured Providers**. If it is missing, click on **Add New Provider** and select **CoreWeave**.
2. Click **Add Key** or edit an existing key.
3. Set a name for your key.
4. Paste your W&B API key directly or use an environment variable (for example, `env.COREWEAVE_API_KEY`).
5. Set **Allowed Models** to **All Models** (default) or the specific model allowlist you want this key to serve.
6. Save the provider configuration.

</Tab>
<Tab title="config.json">

```json
{
  "providers": {
    "coreweave": {
      "keys": [
        {
          "name": "coreweave-key-1",
          "value": "env.COREWEAVE_API_KEY",
          "models": [
            "*"
          ],
          "weight": 1.0
        }
      ]
    }
  }
}
```

</Tab>
<Tab title="API">
Refer to the API documentation for [Provider Keys Management](https://docs.getbifrost.ai/api-reference/providers/create-a-key-for-a-provider).
</Tab>

### Usage tracking with `OpenAI-Project`

An optional `OpenAI-Project: <team>/<project>` header attributes usage to a W&B project. Send it through `extra_headers`:

```json
{
  "providers": {
    "coreweave": {
      "keys": [{ "name": "coreweave-key-1", "value": "env.COREWEAVE_API_KEY", "models": ["*"], "weight": 1.0 }],
      "network_config": {
        "extra_headers": {
          "OpenAI-Project": "my-team/my-project"
        }
      }
    }
  }
}
```

<Warning>
The key must have access to the team, or the gateway returns `403 the inference gateway is not enabled for your organization`.
</Warning>

# 1. Chat Completions

## Request Parameters

Parameters follow OpenAI Chat Completions; see [OpenAI Chat Completions](/providers/supported-providers/openai#1-chat-completions) for the full reference.

Model IDs carry the publisher prefix, so the Bifrost model string is `coreweave/<org>/<model>`, for example `coreweave/openai/gpt-oss-120b` or `coreweave/deepseek-ai/DeepSeek-V4-Flash`. [List Models](#4-list-models) returns the current catalog.

```bash
curl -X POST http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "coreweave/openai/gpt-oss-120b",
    "messages": [{"role": "user", "content": "Hello!"}]
  }'
```

### Reasoning

Reasoning models such as gpt-oss and DeepSeek return reasoning in the assistant message's `reasoning` field, which Bifrost maps to reasoning content. The gateway accepts replayed `reasoning_content` and `reasoning_details` on assistant turns, so Bifrost forwards them unchanged.

### Extra Parameters

Chat and text completion requests pass `extra_params` through untouched. vLLM ignores unknown fields and accepts its own sampling options such as `top_k`, `min_p`, and `chat_template_kwargs`.

### Vision

Multimodal models accept `image_url` parts as public URLs or base64 data URIs. The gateway fetches URLs itself, so a host that blocks automated fetches produces a gateway `403 Forbidden`.

# 2. Responses API

Non-streaming Responses requests go to `/responses` unchanged:

```
BifrostResponsesRequest
  → OpenAI Responses request
  → POST /responses
  → BifrostResponsesResponse
```

Streaming Responses requests go through Chat Completions streaming and come back as Responses stream events:

```
BifrostResponsesRequest
  → ToChatRequest()
  → ChatCompletionStream (/chat/completions)
  → Responses stream events
```

<Note>
The gateway's `/responses` stream sends tool calls as raw `<tool_call>` text and only emits `function_call` items in the final `response.completed` event. Chat Completions streaming emits `tool_calls` deltas as they happen, so Bifrost routes streaming Responses through it.
</Note>

# 3. Text Completions

CoreWeave supports the legacy completions API through `/completions`:

| Parameter | Mapping |
|-----------|---------|
| `prompt` | Sent as-is |
| `max_tokens` | max_tokens |
| `temperature` | temperature |
| `top_p` | top_p |
| `stop` | stop sequences |
| `extra_params` | Passed through |

Responses return `choices[].text`. Streaming uses OpenAI SSE on the same endpoint.

# 4. List Models

`/models` lists the models the key can reach, as `<org>/<model>` IDs.

## Errors

The gateway returns OpenAI-shaped `{"error": {...}}` bodies for authentication failures and flat `{"code", "type", "message"}` bodies for routing errors. Bifrost normalizes both.

| Status | Meaning |
|--------|---------|
| 401 | Invalid or missing API key |
| 402 | Spending cap or credits exhausted for the plan |
| 403 | Key or `OpenAI-Project` header names an organization without gateway access |
| 404 | Model not found |
| 422 / 400 | Invalid request parameters |
| 429 | Concurrency limit reached for the project; Bifrost retries with backoff |
