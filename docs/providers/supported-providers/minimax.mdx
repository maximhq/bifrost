## Overview

The MiniMax provider connects Bifrost to the MiniMax API with bearer authentication and the provider's compatible request and response formats. It supports model listing, chat completions, streaming chat completions, and the Bifrost Responses API through Chat Completions compatibility.

Start with `MiniMax-M3.1-Flash` for text generation; `MiniMax-M3` is also available. Both accept text, image, and video content in chat messages. This input capability is separate from image or video generation, which is not exposed by this provider implementation. Existing configurations and explicitly supplied model IDs are forwarded unchanged.

### Supported Operations

| Operation | Non-Streaming | Streaming | Upstream path |
| --- | --- | --- | --- |
| List Models | Supported | - | `/v1/models` |
| Chat Completions | Supported | Supported | `/v1/chat/completions` |
| Responses API | Supported | Supported | Translated to `/v1/chat/completions` |
| Text Completions | Not supported | Not supported | - |
| Embeddings | Not supported | Not supported | - |
| Image or Video Generation | Not supported | Not supported | - |

## Setup

The default provider origin is `https://api.minimax.io`. Configure a provider key and allow either all models or an explicit model list.

```json
{
  "providers": {
    "minimax": {
      "keys": [
        {
          "name": "minimax-key-1",
          "value": "env.MINIMAX_API_KEY",
          "models": ["MiniMax-M3.1-Flash", "MiniMax-M3"],
          "weight": 1.0
        }
      ]
    }
  }
}
```

For the China endpoint, override the provider origin. Bifrost appends the operation path, so `network_config.base_url` must not include `/v1`.

```json
{
  "providers": {
    "minimax": {
      "network_config": {
        "base_url": "https://api.minimaxi.com"
      },
      "keys": [
        {
          "name": "minimax-cn-key-1",
          "value": "env.MINIMAX_API_KEY",
          "models": ["*"]
        }
      ]
    }
  }
}
```

### Official Regional Endpoints

| Region | OpenAI-compatible base URL | Anthropic SDK base URL | Anthropic messages URL |
| --- | --- | --- | --- |
| Global | `https://api.minimax.io/v1` | `https://api.minimax.io/anthropic` | `https://api.minimax.io/anthropic/v1/messages` |
| China | `https://api.minimaxi.com/v1` | `https://api.minimaxi.com/anthropic` | `https://api.minimaxi.com/anthropic/v1/messages` |

The Bifrost provider uses the OpenAI-compatible `/v1/models` and `/v1/chat/completions` upstream routes. MiniMax also documents a native Responses endpoint at `https://api.minimax.io/v1/responses`. This Bifrost provider currently translates Responses requests to Chat Completions; it does not call that native endpoint. Regional support for native Responses must be verified separately. Anthropic SDK clients use Bifrost's protocol adapter instead of putting an upstream Anthropic URL in `network_config.base_url`:

```python
import anthropic

client = anthropic.Anthropic(
    base_url="http://localhost:8080/anthropic",
    api_key="your-bifrost-virtual-key",
)

response = client.messages.create(
    model="minimax/MiniMax-M3.1-Flash",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Explain this design."}],
)
```

The Anthropic SDK appends `/v1/messages`, so the Bifrost base URL must end at `/anthropic`. Requests then reach `/anthropic/v1/messages`, are normalized by Bifrost, and are dispatched to the selected regional MiniMax OpenAI-compatible endpoint.

## Current Models

| Model | Context window | Input modalities | Thinking |
| --- | ---: | --- | --- |
| `MiniMax-M3.1-Flash` (recommended) | 1,000,000 tokens | Text, image, video | Always on; `adaptive` only |
| `MiniMax-M3` | 1,000,000 tokens | Text, image, video | `adaptive` or `disabled` |

Flash supports up to 524,288 output tokens. Its `reasoning_effort` accepts `low`, `medium`, `high`, `xhigh`, or `max` (default); `none` and disabled thinking are rejected. Flash does not support `service_tier` or `reasoning_split: false`. For MiniMax-M3, the OpenAI-compatible API defaults thinking to `adaptive` and the direct Anthropic-compatible API defaults to `disabled`; effort does not tune depth. Default MiniMax text suggestions show Flash first, then M3 when returned by model discovery. Saved/custom IDs remain usable, and explicit searches or unfiltered administration can still retrieve legacy models.

Provider-specific fields such as `thinking` and `reasoning_split` can be supplied through `extra_params`:

```json
{
  "model": "minimax/MiniMax-M3.1-Flash",
  "messages": [
    {
      "role": "user",
      "content": "Explain the tradeoffs in this design."
    }
  ],
  "extra_params": {
    "thinking": {
      "type": "adaptive"
    },
    "reasoning_split": true
  }
}
```

### Pay-As-You-Go Pricing

Prices are USD per one million tokens. MiniMax-M3.1-Flash uses the following standard-tier prices regardless of input length; MiniMax-M3 pricing depends on service tier and input length.

| Model | Service tier | Input length | Input | Output | Cache read | Cache write |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| `MiniMax-M3.1-Flash` | Standard | Any supported input length | \$0.15 | \$0.60 | \$0.015 | - |
| `MiniMax-M3` | Standard | Up to 512k input tokens | \$0.30 | \$1.20 | \$0.06 | - |
| `MiniMax-M3` | Standard | More than 512k input tokens | \$0.60 | \$2.40 | \$0.12 | - |
| `MiniMax-M3` | Priority | Up to 512k input tokens | \$0.45 | \$1.80 | \$0.09 | - |
| `MiniMax-M3` | Priority | More than 512k input tokens | \$0.90 | \$3.60 | \$0.18 | - |

Set `service_tier` to `priority` to request priority admission for MiniMax-M3. If omitted, the standard tier is used.

See the official [model guide](https://platform.minimax.io/docs/guides/models-intro), [SDK compatibility guide](https://platform.minimax.io/docs/api-reference/text-openai-api), and [pricing page](https://platform.minimax.io/docs/guides/pricing-paygo) for current upstream details.

## Caveats

- The classic `/v1/completions` API is unsupported. MiniMax supports native `/v1/responses`, but Bifrost Responses requests currently use Chat Completions compatibility.
- MiniMax-M3.1-Flash and MiniMax-M3 image and video support applies to chat input content; it does not enable Bifrost image-generation or video-generation operations.
- The China endpoint requires an explicit `network_config.base_url` override.
