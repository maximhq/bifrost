## Overview

Bifrost supports MiniMax's OpenAI-compatible language-model APIs and its native T2A v2 API.

| Operation | Supported | Upstream endpoint |
|---|---|---|
| List Models | ✅ Static catalog | - |
| Chat Completions | ✅ | `/v1/chat/completions` |
| Streaming Chat Completions | ✅ | `/v1/chat/completions` |
| Responses | ✅ | `/v1/responses` |
| Streaming Responses | ✅ | `/v1/responses` |
| Function Calling / Agent loops | ✅ | Chat Completions and Responses |
| Speech | ✅ | `/v1/t2a_v2` |
| Streaming Speech | ✅ | `/v1/t2a_v2` |
| Other operations | ❌ | - |

The default base URL is `https://api.minimax.io`. Users of the China endpoint can set `network_config.base_url` to `https://api.minimax.cn`.

## Supported language models

- `MiniMax-M3`
- `MiniMax-M2.7`
- `MiniMax-M2.7-highspeed`
- `MiniMax-M2.5`
- `MiniMax-M2.5-highspeed`
- `MiniMax-M2.1`
- `MiniMax-M2.1-highspeed`
- `MiniMax-M2`

## Configuration

### MiniMax official API

```json
{
  "providers": {
    "minimax": {
      "keys": [{
        "name": "minimax-key",
        "value": "env.MINIMAX_API_KEY",
        "models": ["*"],
        "weight": 1
      }],
      "minimax_config": {
        "auth_type": "bearer"
      }
    }
  }
}
```

Bearer authentication is the default.

### MiniMax-compatible x-key gateway

```json
{
  "providers": {
    "minimax": {
      "keys": [{
        "name": "gateway-key",
        "value": "env.EXCHANGETOKEN_API_KEY",
        "models": ["speech-2.8-turbo", "speech-2.6-turbo"],
        "weight": 1
      }],
      "network_config": {
        "base_url": "https://api.exchangetoken.ai"
      },
      "minimax_config": {
        "auth_type": "x-key"
      }
    }
  }
}
```

The API key remains in the normal provider key configuration. Bifrost sends it in the `x-key` header when `auth_type` is `x-key`.

## Chat Completions

```bash
curl -X POST http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "minimax/MiniMax-M3",
    "messages": [{"role": "user", "content": "Hello"}],
    "stream": false
  }'
```

MiniMax function tools use the OpenAI-compatible `tools` and `tool_calls` shapes. When tools are present, Bifrost enables MiniMax's `reasoning_split` output unless the caller explicitly provides a value. This lets the agent loop preserve and replay `reasoning_details` between tool rounds, as required for MiniMax interleaved thinking.

Bifrost maps neutral reasoning effort onto MiniMax Chat thinking control:

- `reasoning_effort: "none"` becomes `thinking: {"type": "disabled"}`.
- Any non-`none` reasoning effort becomes `thinking: {"type": "adaptive"}`.
- An explicitly supplied MiniMax `thinking` parameter takes precedence.

MiniMax currently supports only `n=1` for Chat Completions. Large-payload passthrough is rejected for MiniMax Chat and Responses requests because that raw forwarding path cannot safely apply MiniMax reasoning and stream normalization.

## Responses API

```bash
curl -X POST http://localhost:8080/v1/responses \
  -H "Content-Type: application/json" \
  -d '{
    "model": "minimax/MiniMax-M3",
    "input": "Hello",
    "stream": false
  }'
```

Bifrost sends Responses requests to MiniMax's native `/v1/responses` endpoint rather than converting them to Chat Completions. Function tools and full reasoning-item replay are supported. MiniMax currently documents `none` and `auto` as the supported `tool_choice` values; forced or named tool choices are rejected by Bifrost before dispatch.

## Speech request

```bash
curl -X POST http://localhost:8080/v1/audio/speech \
  -H "Content-Type: application/json" \
  -d '{
    "model": "minimax/speech-2.8-turbo",
    "input": "Hello from MiniMax.",
    "voice": "English_expressive_narrator",
    "response_format": "mp3"
  }'
```

Bifrost maps `input` to MiniMax `text`, `voice` to `voice_setting.voice_id`, and `response_format` to `audio_setting.format`. The upstream `output_format` is fixed to `hex` so Bifrost can return decoded audio bytes without making a second URL download.

Provider-specific fields such as `voice_setting`, `audio_setting`, `pronunciation_dict`, `voice_modify`, subtitles, and language boost can be supplied as extra request parameters. Standard Bifrost fields take precedence when both forms set the same value.

When MiniMax returns `subtitle_file`, the non-streaming HTTP endpoint returns the JSON `BifrostSpeechResponse` (audio is JSON base64) so the subtitle URL is available. Streaming responses expose `subtitle_file` on the terminal `speech.audio.done` event.

For streaming requests, Bifrost requests `stream_options.exclude_aggregated_audio=true` to prevent the terminal event from repeating audio already emitted in earlier deltas.
