Koyeb runs the published Bifrost image as a web service with managed TLS. The one-click button carries every setting in its URL and shows them on a review form before the service is created.

<Note>
**Support level: Preview.** This guide is not continuously exercised against a live Koyeb account.
</Note>

The button pre-fills a web service named `bifrost` from `docker.io/maximhq/bifrost:latest` on a `small` instance in `fra`, port `8080` routed at `/`, with the shared [`config.postgres.json`](https://github.com/maximhq/bifrost/blob/main/deploy/config.postgres.json) base64-encoded into `BIFROST_CONFIG_B64`. Koyeb cannot create a database from the button, so three values on the form are placeholders you fill in:

| Variable | What to enter |
|---|---|
| `DATABASE_URL` | The connection string of a Koyeb PostgreSQL database or any PostgreSQL 16 or later reachable from Koyeb. The entrypoint derives `PG_*` from it |
| `BIFROST_ENCRYPTION_KEY` | A long random string. Never change it afterwards |
| `BIFROST_SETUP_TOKEN` | A random string used once to create the first admin account |

Create the database first, in the button's region and inside an app (`bifrost` here; the command creates it when it does not exist, and the service the button creates can live in the same app):

```bash
koyeb databases create bifrost/bifrost-db --region fra --pg-version 16
koyeb databases get bifrost/bifrost-db   # copy the connection string
```

Then click the button, paste the connection string into `DATABASE_URL` and append `?sslmode=require` (or `&sslmode=require` if the string already has a query; Koyeb's copied string has none, and without it the entrypoint falls back to `prefer`, which can downgrade to plaintext on a server that allows it), replace the two secrets, and deploy. When the service is healthy, open its public URL, [create the first admin account](/quickstart/gateway/setting-up-auth) with the setup token, add a provider key, and [create a virtual key](/features/governance/virtual-keys); inference routes require one.

Pin a release tag in the service settings afterwards; the button tracks `latest` so a fresh deploy always gets the current release. The URL is regenerated from [`deploy/koyeb/README.md`](https://github.com/maximhq/bifrost/blob/main/deploy/koyeb/README.md) whenever the shared config changes.

**Enterprise:** on the review form, change the image to the registry path issued for your organization and add the registry secret (server, username, token) in the registry settings before you click deploy; a service created without it cannot pull the private image and the first deployment fails. Koyeb stores the credential as a secret, never in the button URL. Enterprise requires PostgreSQL for both stores.

## Platform requirements

| Setting | Value |
|---|---|
| Container port | `8080`; Koyeb also sets `PORT`, which the entrypoint honours |
| Health check | Koyeb's HTTP check on `/health` (set in the service settings; the button configures the port and route) |
| Storage | PostgreSQL for both stores; Koyeb instances have no persistent disk |
| Instances | One. OSS replicas do not share live configuration |

See [Bifrost Deployment Requirements](/deployment-guides/runtime-contract) for the shared container values.

## Troubleshooting

- Service restarts with an environment error: a placeholder was left in place. Edit the variable and redeploy.
- Cannot connect to the database: Koyeb databases require TLS; keep `?sslmode=require` in `DATABASE_URL` or set `PG_SSL_MODE=require`.
- Port not detected: the button sets `8080;http;/`. Koyeb sets `PORT` to the exposed port and the entrypoint listens on it, overriding `APP_PORT`, so change the exposed port in the service settings rather than `APP_PORT`.
