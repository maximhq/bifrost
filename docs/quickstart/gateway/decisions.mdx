Use decisions to get structured judgments - probabilities, choices, and rubric scores - from judgment models like TypeSafe's jev family. A decision request carries a `state` (what to evaluate) and a map of named `questions`; every question produces one typed answer.

## Provider Model Examples

- TypeSafe: `typesafe/jev-1.13.0`, `typesafe/jev-latest`, `typesafe/jev-preview`
- OpenRouter: `openrouter/typesafe/jev-1.13`, `openrouter/~typesafe/jev-latest`
- OpenAI: `openai/gpt-6-luna`, served by OpenAI's Decisions API (see [OpenAI Decisions API](#openai-decisions-api))

## Basic Request

```bash
curl --location 'http://localhost:8080/v1/decisions' \
--header 'Content-Type: application/json' \
--data '{
  "model": "typesafe/jev-1.13.0",
  "state": "Customer message: I was double charged and nobody replied to my two emails. I want a refund today.",
  "questions": {
    "is_frustrated": {
      "kind": "noul",
      "instructions": "Is the customer frustrated?"
    },
    "category": {
      "kind": "choice",
      "instructions": "Pick the ticket category",
      "criteria": { "billing": "charges and refunds", "bug": "product defects", "other": "anything else" }
    },
    "urgency": {
      "kind": "score",
      "instructions": "Rate how urgently this needs a human reply",
      "criteria": ["can wait a week", "should be answered soon", "needs a reply today"]
    }
  }
}'
```

## Question Kinds

| Kind | Answer value | Criteria |
|------|--------------|----------|
| `noul` | Probability between 0 and 1 | Optional `true`/`false` descriptions |
| `choice` | One option string | Required map of option to description (max 255 options) |
| `score` | Probability-weighted rubric score, including fractions | Required ordered array of 2-10 level descriptions |

`state` and `instructions` accept a plain string or structured data (object or array), preserved losslessly.

## Response

```json
{
  "model": "jev-1.13.0",
  "answers": {
    "is_frustrated": { "kind": "noul", "value": 0.98 },
    "category": {
      "kind": "choice",
      "value": "billing",
      "confidence": 1,
      "probabilities": { "billing": 1, "bug": 0, "other": 0 }
    },
    "urgency": {
      "kind": "score",
      "value": 2,
      "confidence": 1,
      "probabilities": { "0": 0, "1": 0, "2": 1 },
      "legend": { "0": "can wait a week", "1": "should be answered soon", "2": "needs a reply today" }
    }
  },
  "usage": { "prompt_tokens": 437, "completion_tokens": 72, "total_tokens": 509 }
}
```

Every declared question produces an answer of its declared kind. `confidence`, `probabilities`, and `legend` are included when the provider supplies them.

### Provider-Specific Fields

Some decision providers return fields beyond this shape. They appear on the response only when the provider supplies them.

| Provider | Where | Fields |
|----------|-------|--------|
| Laya | Answer | `answer_confidence` (calibrated probability of the reported answer), `action`, and, when `min_confidence` is set, `abstention` (`passed`, `abstained`, or `unevaluated`), `abstention_threshold`, `low_confidence` |
| Laya | Response | `routing`: the checkpoint that answered and why |
| Laya | `usage` | `state_tokens`, `state_tokens_dropped`, `truncated`, `truncated_questions` |

```json
{
  "model": "laya-rl-agent",
  "answers": {
    "urgency": {
      "kind": "score",
      "value": 1.931,
      "confidence": 0.7674,
      "probabilities": { "0": 0.0045, "1": 0.0599, "2": 0.9355 },
      "legend": { "0": "can wait", "1": "soon", "2": "today" },
      "answer_confidence": 0.9355,
      "action": { "act_probability": 1.0 },
      "abstention": "passed",
      "abstention_threshold": 0.9
    }
  },
  "usage": { "prompt_tokens": 39, "total_tokens": 39, "state_tokens": 13, "state_tokens_dropped": 0, "truncated": false },
  "routing": { "model": "english", "reason": "explicit model='english'" }
}
```

## Fallbacks

Standard fallback syntax applies:

```json
{
  "model": "typesafe/jev-preview",
  "fallbacks": ["typesafe/jev-1.13.0"]
}
```

## Validation

Requests are validated before dispatch and rejected with a `400` rather than silently approximated: unsupported kinds, missing instructions, missing choice criteria, score criteria outside 2-10 levels or with non-string entries, and states or instructions that are neither string, object, nor array.

<Note>
TypeSafe's native API is also available 1:1 at `POST /typesafe/v1/systemone` - see the [TypeSafe provider page](/providers/supported-providers/typesafe) for the mapping between the two.
</Note>

## OpenAI Decisions API

OpenAI's Decisions API shape is served at `POST /openai/v1/decisions` (also `/openai/decisions`), so the OpenAI SDKs work with `base_url` set to `http://localhost:8080/openai`. Questions are an ordered list, `name` is optional, and answers come back in request order.

```bash
curl --location 'http://localhost:8080/openai/v1/decisions' \
--header 'Content-Type: application/json' \
--data '{
  "model": "gpt-6-luna",
  "input": "Customer message: I was double charged and nobody replied to my two emails. I want a refund today.",
  "questions": [
    { "type": "predicate", "name": "is_frustrated", "instructions": "Is the customer frustrated?" },
    {
      "type": "choice",
      "name": "category",
      "instructions": "Pick the ticket category",
      "choices": [
        { "value": "billing", "description": "charges and refunds" },
        { "value": "bug", "description": "product defects" },
        { "value": "other" }
      ]
    },
    {
      "type": "score",
      "name": "urgency",
      "instructions": "Rate how urgently this needs a human reply",
      "levels": [
        { "label": "Low", "description": "can wait a week" },
        { "label": "Medium", "description": "should be answered soon" },
        { "label": "High", "description": "needs a reply today" }
      ]
    }
  ]
}'
```

The response is OpenAI's own body: an `answers` array with `probability` for `predicate`, `choice` with `probabilities` and `confidence` for `choice`, and `score` with labelled `probabilities` and `confidence` for `score`. A question the model declines to answer comes back as `{"type": "refusal", "name": ...}`.

This shape is served only by OpenAI decisions models such as `openai/gpt-6-luna`. A request routed to any other provider or model, including through a fallback, is rejected with `400` rather than converted, because the map shape above cannot carry question order, labelled levels, boolean choices, or images.

The map shape on `POST /v1/decisions` also works with `openai/gpt-6-luna`: Bifrost converts it to this shape, calls the Decisions API, and returns the map-shaped answers, so existing `/v1/decisions` callers and the [Complexity Router](/features/complexity-router) can use it without changes. See the [OpenAI provider page](/providers/supported-providers/openai) for how each question kind is converted.

<Note>
OpenAI's Decisions API is in public beta, and `gpt-6-luna` is currently the only model it serves.
</Note>
