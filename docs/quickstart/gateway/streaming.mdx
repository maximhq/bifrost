## Streaming Text Completion

Request text completions with streaming enabled to receive partial `text` chunks as they are generated.

```bash
curl --location 'http://localhost:8080/v1/completions' \
--header 'Content-Type: application/json' \
--data '{
    "model": "openai/gpt-4o-mini",
    "prompt": "Write a short haiku about the ocean",
    "stream": true
}'
```

**Response Format (Server-Sent Events):**
```
data: {"choices":[{"text":"Waves whisper soft"}],"model":"gpt-4o-mini"}

data: {"choices":[{"text":" on distant shores, the moon calls"}],"model":"gpt-4o-mini"}

data: {"choices":[{"text":" tides to rise."}],"model":"gpt-4o-mini"}

data: [DONE]
```

## Streaming Chat Responses

Receive AI responses in real-time as they're generated. Perfect for chat applications where you want to show responses as they're being typed, improving user experience.

```bash
curl --location 'http://localhost:8080/v1/chat/completions' \
--header 'Content-Type: application/json' \
--data '{
    "model": "openai/gpt-4o-mini",
    "messages": [
        {"role": "user", "content": "Tell me a story about a robot learning to paint"}
    ],
    "stream": true
}'
```

**Response Format (Server-Sent Events):**
```
data: {"choices":[{"delta":{"content":"Once"}}],"model":"gpt-4o-mini"}

data: {"choices":[{"delta":{"content":" upon"}}],"model":"gpt-4o-mini"}

data: {"choices":[{"delta":{"content":" a"}}],"model":"gpt-4o-mini"}

data: [DONE]
```

Each chunk contains partial content that you can append to build the complete response in real-time.

> **Note:** Streaming requests also follow the default timeout setting defined in provider configuration, which defaults to **30 seconds**.

<Note>
Bifrost standardizes all stream responses to send usage and finish reason only in the last chunk, and content in the previous chunks.
</Note>

## Responses API Streaming

Stream the OpenAI-style Responses API with event-based SSE. This includes `event:` lines and does not use the `[DONE]` marker; the stream ends when the connection closes.

```bash
curl --location 'http://localhost:8080/v1/responses' \
--header 'Content-Type: application/json' \
--data '{
    "model": "openai/gpt-4o-mini",
    "input": "Tell me one interesting fact about Mars",
    "stream": true
}'
```

**Response Format (Server-Sent Events):**
```
event: response.created
data: {"type":"response.created"}

event: response.output_text.delta
data: {"type":"response.output_text.delta","delta": /* partial text delta payload */ }

event: response.output_text.delta
data: {"type":"response.output_text.delta","delta": * more text delta */ }

event: response.completed
data: {"type":"response.completed","response":{ /* usage, finish_reason, etc. */ }}
```

## Text-to-Speech Streaming: Real-time Audio Generation

Stream audio generation in real-time as text is converted to speech. Ideal for long texts or when you need immediate audio playback.

```bash
curl --location 'http://localhost:8080/v1/audio/speech' \
--header 'Content-Type: application/json' \
--data '{
    "model": "openai/gpt-4o-mini-tts",
    "input": "Hello this is a sample test, respond with hello for my Bifrost",
    "voice": "alloy",
    "stream_format": "sse"
}'
```

**Response:** Audio chunks are delivered via Server-Sent Events. Each chunk contains base64-encoded audio data that you can decode and play or save progressively.

```
data: {"audio":"UklGRigAAABXQVZFZm10IBAAAAABAAEA..."}

data: {"audio":"AKlFQVZFZm10IBAAAAABAAEAq..."}

data: [DONE]
```

**To save the stream:** Add `> audio_stream.txt` to redirect output to a file.

## Incremental Text-to-Speech: Streaming Text In and Audio Out

When the text is still being written, for example by an LLM, open a WebSocket at `GET /v1/audio/speech/stream` and send the text as it arrives. Audio comes back while the sentence is still being generated. Providers: ElevenLabs (`eleven_v4_turbo`) and Soniox (`tts-rt-v2`).

Authentication, virtual keys, budgets and rate limits work as for the other inference endpoints. They are checked once, when the session opens. A session is one logged request, billed by the characters you sent.

The first event must be `speech.config`. It takes the fields of `POST /v1/audio/speech` except `input`, and `model` is `provider/model`. Other fields pass to the provider as they do there.

| Client event | Meaning |
|---|---|
| `speech.config` | Opens the session. `{"type":"speech.config","model":"elevenlabs/eleven_v4_turbo","voice":"<voice id>","response_format":"pcm"}` |
| `speech.text` | Text to speak, `{"type":"speech.text","text":"Hello there, "}`. Send it in pieces. |
| `speech.flush` | Speak what the provider holds and close the current segment. |
| `speech.end` | Flush, then finish. The session closes after `speech.audio.done`. |
| `speech.cancel` | Drop pending text and audio. The session stays open. |

| Server event | Meaning |
|---|---|
| `speech.session.created` | The session is open. Carries `session.id`, `model`, `response_format` and, for raw formats, `sample_rate`. |
| `speech.audio.delta` | Base64 `audio`, the `segment` it belongs to, and `alignment` when `with_timestamps` is true. |
| `speech.segment.done` | The audio of `segment` is complete. |
| `speech.cancelled` | The cancel took effect. Nothing of `segment`, or an earlier segment, follows. |
| `speech.audio.done` | The session is finished. `usage.input_chars` is the characters you sent. |
| `error` | The session could not open, or the provider ended it. |

Segments are numbered from 1. Each flush ends a segment, and a cancel ends every segment still pending. Text sent after a cancel starts a new segment.

Providers hold short text until they have enough to speak it, so send `speech.flush` after a sentence you want spoken now. `speech.end` flushes too. The gateway closes a session that sends nothing for 5 minutes, and a message can be at most 1 MiB. There is no fallback to another provider.

```python
import asyncio, base64, json, websockets

async def speak():
    headers = {"Authorization": "Bearer sk-bf-..."}
    async with websockets.connect("ws://localhost:8080/v1/audio/speech/stream", additional_headers=headers) as ws:
        await ws.send(json.dumps({"type": "speech.config", "model": "elevenlabs/eleven_v4_turbo", "voice": "21m00Tcm4TlvDq8ikWAM", "response_format": "pcm"}))
        await ws.send(json.dumps({"type": "speech.text", "text": "Hello there, this is incremental speech."}))
        await ws.send(json.dumps({"type": "speech.end"}))
        async for message in ws:
            event = json.loads(message)
            if event["type"] == "speech.audio.delta":
                audio = base64.b64decode(event["audio"])  # play or save it
            elif event["type"] == "speech.audio.done":
                print("characters billed:", event["usage"]["input_chars"])

asyncio.run(speak())
```

**ElevenLabs:** the session uses the text-to-dialogue socket, which takes one voice. It has no cancel, so a cancel closes the provider connection and the next text opens a new one.

**Soniox:** `language_code` is required. Soniox has no flush, so each segment is a Soniox stream: a flush ends the stream and the next text opens another. A stream that gets no text for 3 seconds is ended the same way, which makes the pause a segment boundary. Raw `pcm` is 24 kHz unless `sample_rate` is set.

## Speech-to-Text Streaming: Real-time Audio Transcription

Stream audio transcription results as they're processed. Get immediate text output for real-time applications or long audio files.

```bash
curl --location 'http://localhost:8080/v1/audio/transcriptions' \
--form 'file=@"/path/to/your/audio.mp3"' \
--form 'model="openai/gpt-4o-transcribe"' \
--form 'stream="true"' \
--form 'response_format="json"'
```

**Response Format:**
```
data: {"text":"Hello"}

data: {"text":" this"}

data: {"text":" is"}

data: {"text":" a sample"}

data: [DONE]
```

**Additional options:** Add `--form 'language="en"'` or `--form 'prompt="context hint"'` for better accuracy.

## Audio Format Support

**Speech Synthesis:** Supports `"response_format": "mp3"` (default) and `"response_format": "wav"`

**Transcription Input:** Accepts MP3, WAV, M4A, and other common audio formats

> **Note:** Streaming capabilities vary by provider and model. Check each provider's documentation for specific streaming support and limitations.
