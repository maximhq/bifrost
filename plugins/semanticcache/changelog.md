- chore: upgraded Go to 1.27.4, core to v1.16.0 and framework to v1.13.0
- fix: a follow-up turn no longer matches an earlier turn of the same conversation; earlier messages must match exactly and only the newest message is compared by meaning
- fix: requests that differ only in text.format (schema, name, strict), n, audio, top_k, reasoning (max_tokens, summary, display, mode, type, context), web_search_options, mcp_servers or container no longer share a cache entry. This changes the cache key for every Responses request that sends text.format, including a plain {"type":"text"}, and for chat or Responses requests that set any of the newly hashed params, so those requests miss once after upgrading; the old entries stay until their TTL expires. Provider-specific extra params now sit under their own key in the cache identity, so a request field can no longer stand in for a value the plugin derives (stream, attachments or any *_hash); requests that send extra params also miss once [@kunalgoesbyken](https://github.com/kunalgoesbyken)
