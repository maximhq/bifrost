- fix: under `convert_chat_to_responses`, a chat completion carrying function tools to a reasoning model whose datasheet row says `supports_reasoning_with_tool_calls: false` and lists `/v1/responses` is now served through the Responses API with the caller's reasoning effort intact, instead of having its reasoning disabled. Azure Foundry `gpt-6-astra` / `gpt-5.6-*` reject tools + `reasoning_effort` on `/v1/chat/completions` and also reject `reasoning_effort: "none"`, so the previous fallback could never succeed there. Models that support the combination on chat, or that cannot reach `/v1/responses`, are unchanged (#7275)
- fix: removed the namespace-tool flattening that ran under `should_convert_params`; it spliced nested functions into the top-level list without a namespace prefix, so two namespaces sharing a function name produced duplicate tool names and an upstream 400. Flattening now lives in Bifrost core for every provider whose wire lacks the `namespace` type, with unique `<namespace>__<function>` names and response-side mapping back. `should_convert_params` is still accepted so existing configs load, but it no longer changes any request (#7048)
