[feat]: multi-pod config sync via PostgreSQL LISTEN/NOTIFY. `BifrostHTTPServer` starts a background listener at the end of `Bootstrap` when the config store is Postgres-backed, dispatching received config change events to the same reload methods (`ReloadProvider`, `ReloadClientConfigFromConfigStore`, `ReloadRoutingRule`, `ReloadTeam`, `ReloadCustomer`, `ReloadModelConfig`, `ForceReloadPricing`, and their `Remove*` counterparts) the REST API handlers already call after a write, so a provider/key/virtual-key/MCP-client/routing-rule/team/customer/budget/model-config/pricing-override change made on one pod now reaches every other pod without a restart. A synthetic `full_reload` event is dispatched on every (re)connect to catch up on anything missed while disconnected. The listener is stopped gracefully during server shutdown
